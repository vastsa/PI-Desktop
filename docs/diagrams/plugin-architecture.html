PI-Desktop 插件模块架构

宿主提供能力、插件声明能力：清单校验在 Rust 侧，权限闸门与 API 白名单在 Electron 主进程， 插件代码在每插件一个 utilityProcess 里跑，只能通过 JSON RPC 回喊宿主。

已实现 代码中可验证 部分实现 有接口/有降级 缺口 仅规格、尚未落地 点击任意节点查看职责与文件位置

    二、五条关键链路

    任一步失败即整体回滚：卸载子进程、清空契约、记 plugin.load.error；启用触发的加载失败会自动禁用插件（D017）。宿主启动不受影响。

    1. 1MainloadFromPath() 读 manifest.json → validateManifest（id/name/version/main/schemaVersion 全必填）；旧实例先卸载
    2. 2Main校验入口文件存在，计算授权集合：安装期授权优先，未授权的声明项不会在此被拒——真正的拒绝发生在调用时
    3. 3ChildutilityProcess.fork，serviceName pi-plugin-<id>，stdio 管道回收成审计日志
    4. 4Child收到 init 帧 → 注入 globalThis.pi → require 插件模块（ERR_REQUIRE_ESM 时回退动态 import）→ 调 onLoad()
    5. 5ChildonLoad 期间反向 RPC：commands.register / agent.registerTool；注册失败则子进程侧同步回滚本地 Map
    6. 6Main整个 init 有 15s 预算；成功后记 plugin.load.success，命令进面板、工具进下一次会话参数

    插件工具不在 Rust 侧执行——host-core 只认前缀并把执行权交回桌面端，因此工具代码始终留在插件自己的进程里。

    1. 1Sidecar模型发起 tool_use，工具名形如 plugin_demo_hello_echo
    2. 2host-coreplugin_ 前缀命中 → 不本地执行，改发 plugins.execute 通知（executionId + toolCallId）
    3. 3Main按 fullName 在注册表找工具；找不到即 TOOL_NOT_FOUND
    4. 4Childtool.execute 帧下发，预算 110s（压在 host-core 120s 之下，好让插件侧错误先返回）
    5. 5Child执行 tool.execute(args, ctx)，ctx 提供 sessionId/turnId/log；抛错归一化为 TOOL_FAILED
    6. 6host-coreplugins.resolveExecution 回填结果 → 进模型上下文；同时 logger.app 落审计、drainToasts 推 UI

    卸载默认删数据（D016）；MVP 不允许插件设置里放密钥（D018）。自动更新逐插件 opt-in，且拒绝静默扩权。

    1. 1Renderer目录 / .piplug / 市场三个入口，统一走 installFromPath · installFromPackage · market.install
    2. 2host-core解包前置校验：仅 store 压缩、文件数/字节上限、无符号链接、路径不得穿越、sha256 与期望值一致
    3. 3host-core写入 plugins/installed/<id>，登记 registry.json（source / status / marketplace / autoUpdate）
    4. 4Renderer权限评审：新增权限算 permission_diff 并强制确认；未识别的权限按高风险显示
    5. 5host-coreplugins.grantPermissions / revokePermissions 持久化授权集合；撤权需重载才对运行中的插件生效
    6. 6Main启用 → 按 registry 的授权集合调 loadFromPath；重启时同样按 registry 恢复（dev 源的继续挂 watcher）

    面板与宿主渲染进程完全隔离：独立 session 分区、sandbox、无 Node 集成、禁用 webview；它的 13 条桥接通道复用与插件主进程同一套权限闸门。

    1. 1Child插件调 pi.ui.openPanel() → 闸门要求 ui.panel，且清单必须声明 ui.panel 路径且文件存在
    2. 2MainPanelHost 建窗：persist:pi-plugin-<id> 分区、sandbox: true、contextIsolation: true、nodeIntegration: false
    3. 3Panel页面以 file:// 载入插件自带 HTML，仅能用 preload 暴露的 pi-plugin-panel-invoke
    4. 4Main按 event.sender.id 反查 pluginId——面板不能自称身份；查不到直接拒绝
    5. 5MaininvokePanelBridge 把通道映射到同一份 hostApi(loaded)：ui.* / fs.* / clipboard.* / shell / net / settings / workspace
    6. 6Main插件卸载或崩溃时自动 closePanel，窗口不会变成孤儿

    热重载的核心约束：权限只能收窄不能放宽。选目录那一刻记录的授权集合是此后所有重载的天花板。

    1. 1Main递归 fs.watch；node_modules/.git/dist/target 与编辑器临时文件（.DS_Store、~、___jb_）全部忽略
    2. 2Main300ms 去抖：保存全部/格式化/打包会连写多文件，一批只重载一次；定时器 unref，不拖住退出
    3. 3Main重读清单声明的权限，与记录的天花板比对；出现新增项 → PERMISSION_DENIED，要求重新走加载评审
    4. 4Main作者删掉的权限会跟着消失：授权跟随清单向下，不向上
    5. 5Main卸载 → 重新加载；reloading 标记让 watch 与天花板活过这次卸载，语法错误修好后照样能被接住
    6. 6RendereronPluginReloaded → event/pluginChanged，页面从宿主重读状态而不是相信这次编辑

    三、权限矩阵：声明 → 解锁的 API → 闸门位置

    权限风险解锁的宿主 API额外约束（代码中实际存在的）
    ui.panel低ui.openPanel / closePanel清单必须声明面板路径且文件存在
    notify低ui.notify—
    clipboard.read中clipboard.readText成功即写审计
    clipboard.write中clipboard.writeText成功即写审计
    shell.openExternal中shell.openExternal仅 http(s) / mailto，否则 INVALID_ARGUMENT
    fs.read.workspace中fs.readText · fs.globensureWithinRoot 拦路径逃逸；glob 结果截断到 500
    fs.write.workspace高fs.writeText同样限工作区内；自动建父目录
    fs.delete.workspace高fs.remove限工作区内；非递归；拒绝删除工作区根目录
    agent.tool.register高agent.registerTool强制改名 plugin_<id>_<tool>；卸载即摘除
    agent.prompt.inject高contributes.skills 注入未授权时整包技能跳过并记 plugin.skills.denied
    net.fetch高net.fetch仅 http(s)；默认 15s 超时；记 url + status

    未在此表中的权限字符串：UI 按高风险显示，devkit check 报 permission.unknown，运行时因为不解锁任何 API 而等于无效。

    四、插件能贡献什么

    四类契约点

    • commands — 进全局命令面板，command.run 回子进程执行，预算 30s
    • agentTools — 带 JSON Schema 与 risk 等级，暴露给模型
    • skills — Markdown（可带 front matter name/description），每次组会话参数时重读，改文件下一轮生效
    • settings — 默认值来自清单，落 plugins/data/<id>/settings.json；MVP 不收密钥

    清单骨架

    {
  "schemaVersion": 1,      // 缺失即拒装
  "id": "demo.hello",
  "version": "0.1.0",
  "main": "main.js",
  "ui": { "panel": "renderer/index.html" },
  "contributes": {
    "commands":   [ … ],
    "agentTools": [ … ],
    "skills":     [ "./skills/x.md" ],
    "settings":   [ … ]
  },
  "permissions": [ … ],
  "engines": { "piDesktop": ">=0.1.0" }
}

    超时预算（分层收敛）

    • PLUGIN_LOAD_TIMEOUT_MS — 15s（模块求值 + onLoad）
    • PLUGIN_HOOK_TIMEOUT_MS — 5s（onUnload）
    • PLUGIN_COMMAND_TIMEOUT_MS — 30s（面向用户，快速失败）
    • PLUGIN_TOOL_TIMEOUT_MS — 110s（< host-core 的 120s）
    • watcher 去抖 300ms / 最多 16 个开发插件

    五、隔离边界：拦得住什么 / 还拦不住什么

    已经成立的保证

    • 插件拿不到任何宿主对象，也无法 require 宿主模块——只有 JSON 帧
    • 插件进程崩溃被收敛：拒绝在途调用、清契约、关面板、发 toast + pluginChanged，宿主不退出
    • 白名单 + 闸门都跑在宿主，插件改不动判定逻辑；越界 API 直接 UNSUPPORTED 并留审计
    • 面板是独立分区的 sandbox 窗口，且身份由 sender 反查，不可伪造
    • 宿主 env 中的 provider key / shell 密钥不进插件进程
    • 技能与工具的变化会改指纹，从而拒绝复用旧提示词的会话
    • 热重载不能扩权；升级新增权限必须显式确认

    明确未闭合的缺口

    • 高 插件进程内没有能力沙箱：pi.* 之外仍可直接用 Node 内建，因此权限模型只覆盖 brokered API；市场包实质是用户权限代码
    • 高 无 CPU / 内存限额，也没有逐次调用确认
    • 中 生命周期只有 onLoad/onUnload：install/enable/disable/uninstall 钩子仅在 API 中声明
    • 中 events.on/off 未桥接，目前是可调用的空实现
    • 中 签名验签未实现：只有 sha256 完整性校验；signature 字段已在协议里预留
    • 低 agent.invokeSkill / appendSystemHint 仍是规划项
