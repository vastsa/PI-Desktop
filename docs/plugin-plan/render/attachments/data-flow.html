附件 · 数据流

内容怎么进暂存区、列表怎么按来源裁、移除怎么限在自己名下。六节固定：接口约定 / 数据怎么走 / 出错怎么办 / 不提供什么 / 相关条目 / 还没定的事。

status: draft · issue #545 · #561 · S1 红线：禁 path / file:// / URL 引用

1接口约定 已拍板

三个动作。add 只收内容或凭证；list / remove 只限自己名下。

// ① 加
attachments.add({ name, mimeType, content | token })
// → { id }

// ② 列 —— 只见自己的
attachments.list()
// → [{ id, name, mimeType, size }]

// ③ 移 —— 只能动自己的
attachments.remove(id)
// → { ok: true }

字段

字段含义
name显示名，必须带扩展名
mimeType类型；决定缩略图还是文件芯片
content | token二选一：内容本体，或宿主认识的取内容凭证
id宿主登记后分配；移除、引用都用它
S1 红线写入拒绝层。path / file:// / URL 引用一律拒绝；裸路径附件不进暂存区。

2数据怎么走 已拍板

host 暂存区 / 附件登记 slot 动作边界 plugin 插件渲染器
路径方向怎么走
加插件 → 宿主交 { name, mimeType, content|token } → 宿主校验（拒路径 / 拒无扩展名）→ 落暂存区 → 分配 id 回插件
列宿主 → 插件按来源过滤：只回本插件加的那几条
移插件 → 宿主校验 id 归属：是自己的才删；不是 → 拒绝，列表不变
发宿主发送时从暂存区取内容，当正常附件随消息走
清宿主切会话 / 删会话：暂存区与登记一并清空

归属怎么记

  • 每条附件记一个来源：用户，或某个插件。
  • list 的过滤和 remove 的闸，都看这个来源标记。
  • 来源标记由宿主注入，插件不能自填——不然就能冒名动别家的。
暂存区生命周期。随会话走：切会话即清空，随会话删除。插件交完内容后不再持有地址；旧「插件自存、只登记 ref」作废（那条路会把读盘 / 上网的责任甩给宿主）。

3出错怎么办 已定

情况结果靠什么保证
给了 path / file:// / URLadd 整次拒绝（S1 红线）入参校验
content 与 token 都没给 / 都给了add 整次拒绝二选一校验
name 没扩展名add 整次拒绝名字校验
remove 别人 / 用户的 id拒绝，列表不变归属闸
id 不存在拒绝存在性检查
插件被禁用 / 卸载它加的附件仍留在暂存区（随会话），但本插件再也 list / remove 不到生命周期
切会话暂存区清空，旧 id 全部作废会话边界

4不提供什么 已定 · 含 S1 红线

不给为什么
path / file:// / URL 引用S1 红线：不让宿主替插件读盘或上网；裸路径附件拒绝
别家 / 用户附件的可见与操作list 只见自己的；remove 只动自己的
改附件只有加 / 列 / 移；换内容就移除后重加
跨会话附件暂存区随会话走
自填来源标记归属由宿主注入，防冒名
草稿文字归 render/draft/

6还没定的事

  • token 的具体形态：一次性凭证、宿主句柄，还是别的。
  • 暂存区单条 / 总量上限，超限错误码。
  • 插件卸载后其附件是否保留到发送（当前：保留在暂存区、随会话）。
