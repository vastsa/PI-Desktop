附件 · 需求

附件区三动作：attachments.add / attachments.list / attachments.remove。只收内容或凭证；宿主落暂存区；可见性与操作都只限自己。

status: draft · issue #545 · #561 · S1 红线：禁 path / file:// / URL 引用

范围 已定

  • 三个动作，管输入框附件区：
    • attachments.add — 加一条附件（内容或凭证，宿主落暂存区）
    • attachments.list — 列出自己加的
    • attachments.remove — 移除自己加的
  • 不谈：草稿文字（render/draft/）、附件界面槽（ui/composer/）、发送时的取内容细节（实现期）。

契约形状 已拍板

// ① 加 —— 只收内容或凭证
attachments.add({
  name: "chart.png",          // 显示名，必须带扩展名
  mimeType: "image/png",       // 决定画图片缩略还是文件芯片
  content | token               // 二选一：内容本体，或取内容的凭证
})
// → { id }
// 拒绝：path / file:// / URL 引用；名字没扩展名

// ② 列 —— 只见自己加的
attachments.list()
// → [{ id, name, mimeType, size, … }]

// ③ 移 —— 只能动自己加的
attachments.remove(id)
// → { ok: true }
// 拒绝：id 不存在，或那条不是本插件加的
方面内容
add 入参只收 { name, mimeType, content|token }
内容保管宿主落进暂存区；插件交完就不再持有地址
list 可见性只列自己的——用户加的、别家插件加的，看不见
remove 边界只能动自己的——别人的、用户的，一律拒绝
S1 红线（拍板）。禁止 path / file:// / URL 引用。插件不得只交一个本地路径或网络地址让宿主去读；也不得把裸路径塞进附件。内容进暂存区的只有两条路：content 本体，或宿主认识的 token 凭证。踩线整次拒绝。
宿主暂存区（拍板）。内容由宿主收下并保管，插件不再「自己存一份、只登记地址」。发送时宿主从暂存区取内容，当正常附件随消息走。暂存区随会话走：切会话即清空。

场景 典型用法

#场景动作
1图表插件生成 chart.png，交进附件区，随下一条消息发走add（content）
2导出插件把报告 PDF 交进来add（content 或 token）
3插件在自己的按钮弹层里列出「我加的附件」list（只回自己的）
4插件清理自己刚才那条失败产物remove（只动自己的）

明确不做 已定 · 含 S1 红线

  • S1 红线：禁 path / file:// / URL 引用。不收「本地路径」「文件协议地址」「网络地址」当附件内容。裸路径附件 → 整次拒绝，写进拒绝层。
  • 不让插件碰别人的附件。list 不见别家与用户；remove 动不了别家与用户。
  • 不让插件自己保管地址。内容进宿主暂存区，旧「插件自存、只登记 ref」作废。
  • 不做跨会话附件。暂存区随会话走，切会话即清空。
  • 不管草稿文字。那是 render/draft/。
  • 不给「改附件」。只有加 / 列 / 移；要换内容就移除后重新加。
