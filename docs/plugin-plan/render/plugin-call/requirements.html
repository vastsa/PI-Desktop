插件转发 · 需求

渲染侧组件取自己插件的私有数据：dispatch("plugin.call")。一问一答、JSON 应答；method 白名单、体积、限速、超时、熔断五道约束；pluginId 宿主注入。

status: draft · issue #545 · #561 · 出站分层：核心 P

范围 已定

  • 一个渲染侧动作：dispatch("plugin.call")——槽组件向自己这个插件要一份数据。
  • 链路固定：dispatch → 校验声明 → 跨进程转发 → 本插件应答 → JSON 回来。
  • 不谈：跨插件调用（禁止）、推流 / 订阅（禁止）、宿主能力调用（那是别的出站词）。

契约形状 已拍板

// ① 组件侧发起
const data = await dispatch("plugin.call", {
  method: "searchKb",
  args:   { query: "退货政策" }
})
// pluginId 不出现在这里——宿主注入，不可自填

// ② 跨进程载荷（宿主组装）
IPC plugin/renderer/call
  { pluginId, method, args }

// ③ 插件侧应答
onRendererCall(method, args) → JSON 值
方面内容
链路dispatch → 校验声明 → IPC plugin/renderer/call {pluginId, method, args} → 本插件 onRendererCall → JSON 应答
method白名单——只认插件声明过的；没声明 → PLUGIN_CALL_NO_HANDLER
载荷args 与应答合计 ≤64KB；超限拒绝
限速QPS；超速拒绝
超时2s；超时 PLUGIN_CALL_TIMEOUT
熔断连续失败 → PLUGIN_CALL_DISABLED，本插件转发暂时关掉
pluginId宿主注入，不可自填——只能调自己，冒充别家直接拒绝
应答JSON——不能是流、不能是函数、不能是循环引用
不能推流（拍板）。一问一答，返回值必须能变成 JSON。要持续数据就多次调用，或者去订阅宿主的推送通道——本接口不是流。
pluginId 宿主注入（拍板）。组件侧只能写 method 和 args；「这是谁」由宿主在跨进程载荷里补上。这样就堵死了冒充别家插件、绕过归属闸的路。

谁能用 已定

谁怎么用
槽组件（渲染侧）dispatch("plugin.call", …)，只可调自己这个插件
本插件 main实现 onRendererCall，答 JSON
别家插件不能——pluginId 不可自填，跨插件调用拒绝

场景 典型用法

#场景
1知识库槽组件要搜自己插件索引里的条目，答一份列表
2工具卡要取自己插件侧的运行摘要，答一个对象
3触发符列表要去自己的数据源里筛，答候选数组

明确不做 已定

  • 不能推流。不是订阅、不是事件源；一问一答，JSON 应答。
  • 不能跨插件。pluginId 宿主注入，只能调自己；冒充别家拒绝。
  • 不给未声明的 method。白名单外一律 NO_HANDLER。
  • 不限于「取数」的副作用不走这里。写草稿、加附件、复制、打开链接——走各自的出站词，不在 plugin.call 里开后门。
  • 失败不静默。超时、超限、熔断都带码返回，不假装成功。
  • 连续失败不无限重试。熔断 PLUGIN_CALL_DISABLED，先歇着。
