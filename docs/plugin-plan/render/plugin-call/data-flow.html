插件转发 · 数据流

一次 plugin.call 的往返：组件发起、宿主校验并注入身份、跨进程到本插件、JSON 答回来。六节固定：接口约定 / 数据怎么走 / 出错怎么办 / 不提供什么 / 相关条目 / 还没定的事。

status: draft · issue #545 · #561 · 出站分层：核心 P · 字段名是建议值

1接口约定 已拍板

一个渲染侧动作 plugin.call，出站分层里的核心 P。一问一答，JSON 应答，不能推流。

// 组件侧
const data = await dispatch("plugin.call", { method, args })

// 跨进程载荷（宿主组装，pluginId 不可自填）
IPC plugin/renderer/call
  { pluginId, method, args }

// 插件侧
onRendererCall(method, args) → JSON 值

约束五件套

约束值违反时
method 白名单只认声明过的PLUGIN_CALL_NO_HANDLER
载荷≤64KBPLUGIN_CALL_TOO_LARGE
限速QPSPLUGIN_CALL_RATE_LIMITED
超时2sPLUGIN_CALL_TIMEOUT
熔断连续失败PLUGIN_CALL_DISABLED

出站分层（公共）

层词约束
核心 Hentry.copy · message.mutate · composer.insertText · attachments.addmutate 宿主确认 + 必审计；add 只收 content|token
核心 P（本接口）plugin.call白名单 · ≤64KB · QPS · 2s 超时 · 熔断 · pluginId 宿主注入
核心 FmeasureHeight · deriveSummary同步 16ms · 超时回默认 · F 内禁调 H/P
可选 Htoast · ask · clipboard.write · host.open · composer.readDraft · attachments.list/removeclipboard.write 须同次用户手势
拒绝远端 replaceDraft · 裸路径附件P 返回不得静默改用户数据
边界一句话。F = 渲染线程内同步纯函数；H/P = 跨进程异步 dispatch。plugin.call 是 P——慢、可能失败、有额度；F 内不得调它。

2数据怎么走 已拍板

host 宿主校验 / 转发 slot 接口边界 plugin 槽组件 · 本插件 main
  1. dispatch — 槽组件发起 dispatch("plugin.call", { method, args })。这里没有 pluginId。
  2. 校验声明 — 宿主查：method 在白名单吗？载荷超 64KB 吗？超 QPS 吗？熔断中吗？任一不过，直接带失败码返回，不往下走。
  3. 跨进程转发 — 宿主组装 IPC plugin/renderer/call { pluginId, method, args }。pluginId 由宿主注入，组件填不了。
  4. 本插件应答 — 该插件的 onRendererCall(method, args) 跑起来，吐出一个 JSON 值。
  5. JSON 回来 — 应答原路回到组件的 await，落定为那个 JSON 值；2s 内没回到 → TIMEOUT。

递交模型

  • 请求 / 应答，一次一个来回。不是订阅，不是推流。
  • 身份单向：pluginId 只能由宿主注入，组件侧不可见、不可写。
  • 方向单一：组件 → 自己的 main。反向（main 主动推给组件）不走本接口。
  • 生命周期：随插件走。插件卸载 → 挂起的调用落定失败码，不悬空。

3出错怎么办 已定

情况结果码
method 没声明 / 没实现拒绝PLUGIN_CALL_NO_HANDLER
args / 应答不能变 JSON拒绝PLUGIN_CALL_UNSERIALIZABLE
2s 内没答上超时落定PLUGIN_CALL_TIMEOUT
超过 64KB拒绝PLUGIN_CALL_TOO_LARGE
超过 QPS拒绝PLUGIN_CALL_RATE_LIMITED
连续失败熔断，暂时关掉本插件转发PLUGIN_CALL_DISABLED
插件被禁用 / 卸载挂起调用落定失败生命周期清理
尝试冒充别家拒绝（pluginId 不可自填）身份闸
失败不静默。每一种拒绝都带码回来，调用方能区分「没这个方法」和「太慢了」和「被熔断了」。P 的返回不得静默改用户数据——应答只是数据，副作用另走 H 词。

4不提供什么 已定

不给为什么
推流 / 订阅一问一答，JSON 应答；要持续就多次调，或走宿主推送通道
跨插件调用pluginId 宿主注入，只能调自己
白名单外的 method声明制，不给后门
借道做副作用写草稿 / 加附件 / 复制 / 打开链接——各有出站词，不在这里开
无限重试连续失败就熔断 PLUGIN_CALL_DISABLED
在同步纯函数里调F 内禁 H/P（16ms 同步预算）
