确认卡 · 需求

插件向用户问一句话：确认 / 二选一 / 知会。接口名 ui.ask（原 ui.confirm 语义，改名消歧）。返回恒为对象，卡壳宿主固定，按钮配置化。

status: draft · issue #545 · #561 · 出站分层：可选 H

范围 已定

  • 一个渲染侧接口：ui.ask——插件发起一次确认 / 选择 / 知会，等用户点一个按钮。
  • 卡壳宿主固定，内容与按钮走参数；返回恒为 { choice, reason? }。
  • 不谈：自理弹窗 / 悬浮层（ui/self-dialog/）、宿主权限审批卡、agent 侧的布尔确认。

契约形状 已拍板

// 调用（插件渲染器内）
const result = await pi.ui.ask({
  title: "分支清理 · 确认删除",
  description: "将删除 feat/528 等 3 个分支",
  actions: [
    { id: "cancel",  label: "取消",     variant: "ghost" },
    { id: "delete",  label: "全部删除", variant: "primary" },
  ],
})

// 返回：恒为对象，禁止 string | object 两态
{ choice: "delete" }
{ choice: "cancel",  reason: "plugin-unloaded" }
方面内容
入参title 一行；description? 说明；actions[] 按钮配置（id / 文案 / 档位）
返回恒 { choice, reason? }。choice = 被按下的按钮 id；reason 只在非正常点击时出现
卸载插件被禁用 / 卸载 → { choice: "cancel", reason: "plugin-unloaded" }，挂起的等待一并落定
卡壳宿主固定（输入框上方同宽横栏）；插件不能换外形、不能往卡里塞自己的界面
按钮配置化：文案、档位（ghost / secondary / primary）；样式宿主定
出站层可选 H（与 toast、clipboard.write、host.open、readDraft、list / remove 同档）
禁止两态返回（拍板）。旧写法有时回字符串、有时回对象，调用方要写两套判断。现在一律对象：choice 永远在，reason 可选。卸载也走对象，不再抛特殊值。
固定卡壳、配置化按钮（拍板）。卡壳和按钮样式是宿主的；插件只交标题、说明、按钮清单。卡片里没有插件代码在跑——排版和点击分发都是宿主的。

谁能用 已定

谁怎么用权限
插件渲染器代码在自己的界面 / 交互里 await pi.ui.ask(...)随渲染档（renderer.extension），不单列
插件 headless不能用——没有界面侧，问不出用户—

场景 典型用法

#场景按钮配置
1危险操作前确认：删分支、清缓存取消 + 主按钮「删除」
2二选一：覆盖还是追加两个同级按钮

明确不做 已定

  • 不接管宿主权限审批卡。那张卡是安全决策面，只属于宿主；旧接管槽取消。ui.ask 永远不进权限队列的决策路径。
  • 不接受组件、不让自绘。卡片里没有插件渲染的界面；内容只有 title + description 固定字段。
  • 禁止 string | object 两态返回。恒 { choice, reason? }。
  • 不给层机制。确认卡不走注册、不参与层级仲裁；要自由界面走 ui/self-dialog/。
  • 同名不同物——必须消歧。agent 侧也有一个「确认」，返回的是布尔（允许 / 拒绝），走的是工具审批路径；本接口是渲染侧问用户一句话，返回 { choice, reason? }。本接口定名 ui.ask，不再叫 confirm。两者不得混用同一返回形状。
消歧一句话。问用户点哪个按钮 → ui.ask（本目录）。工具要不要放行 → agent 侧布尔确认（宿主审批卡）。名字撞车是历史问题，改名是消歧手段，不是别名。
