确认卡 · 数据流

一次 ui.ask 的往返：插件发起、宿主排卡、用户点按钮、结果落定。六节固定：接口约定 / 数据怎么走 / 出错怎么办 / 不提供什么 / 相关条目 / 还没定的事。

status: draft · issue #545 · #561 · 字段名是建议值，结构是拍板的

1接口约定 已拍板

一个渲染侧接口 ui.ask，出站分层里的可选 H。返回恒为对象。

// 插件渲染器内
const { choice, reason } = await pi.ui.ask({
  title, description?, actions: [{ id, label, variant? }]
})
// choice = 被按下的按钮 id
// reason = 仅非正常点击时出现，例如 "plugin-unloaded"

返回形状（恒定）

情况返回
用户点按钮{ choice: "<actionId>" }
插件被禁用 / 卸载{ choice: "cancel", reason: "plugin-unloaded" }
禁止 string | object 两态。老契约里有时直接回按钮 id 字符串、卸载时回对象——调用方要写两套分支。现在一律 { choice, reason? }。

出站分层（公共，本接口落在「可选 H」）

层词约束
核心 Hentry.copy · message.mutate · composer.insertText · attachments.addmutate 宿主确认 + 必审计；add 只收 content|token
核心 Pplugin.callmethod 白名单 · ≤64KB · QPS · 2s 超时 · 熔断 PLUGIN_CALL_DISABLED · pluginId 宿主注入
核心 FmeasureHeight · deriveSummary同步纯函数 · 16ms · 超时回默认 · F 内禁调 H/P
可选 H（本接口）toast · ui.ask · clipboard.write · host.open · composer.readDraft · attachments.list/removeclipboard.write 须同次用户手势
拒绝远端来源的 replaceDraft · 裸路径附件不得静默改用户数据

2数据怎么走 已拍板

host 宿主确认卡 slot 接口边界 plugin 插件渲染器
时刻谁发生什么
调用插件await pi.ui.ask(...)，入参校验通过后进宿主卡片队列
排队宿主插件确认卡先进先出；权限审批卡随时插队（安全优先，不是公平队列）
上屏宿主轮到它时，固定卡壳出现在输入框上方同宽横栏；标题 / 说明 / 按钮由参数排版
显示中宿主内容定格；卡里没有插件代码在跑
点击用户 → 宿主按下按钮 → 卡片移除 → Promise 落定 { choice } → 下一张上屏
卸载宿主插件被禁用 / 卸载 → 卡片（含排队中的）移除，挂起的 await 落定 { choice:"cancel", reason:"plugin-unloaded" }
返回方向单一。只有「按钮 id + 可选原因」这一条窄通道回插件；卡片拿不到会话内容，插件也拿不到卡壳内部结构。

3出错怎么办 已定

情况结果靠什么保证
调用参数不合法调用被拒绝并带错误码（按钮超限、字段缺失），不产生卡片入参校验
插件被禁用 / 卸载卡片移除；挂起的等待落定 { choice:"cancel", reason:"plugin-unloaded" }插件生命周期清理
权限审批卡插队插件卡退回队列，处理完按原顺序恢复安全优先的队列规则
用户不点、一直挂着不超时、不响应 Esc；直到点击或卸载才落定卡片生命周期

4不提供什么 已定

不给为什么
宿主权限审批卡的接管 / 重画安全决策面只属于宿主；ui.ask 不进权限决策路径
卡里的自绘 / 组件内容只有固定字段；卡片里不跑插件代码
string 返回禁止两态；恒 { choice, reason? }
层机制 / 注册 / 仲裁确认卡不是 UI 槽
会话 / 消息数据卡片只负责问用户
与 agent 侧布尔确认共用形状同名不同物：那边是允许 / 拒绝布尔，这边是按钮选择对象
