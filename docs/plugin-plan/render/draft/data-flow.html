草稿读写 · 数据流

草稿快照怎么读、文字怎么写回去、变化怎么推给插件。六节固定：接口约定 / 数据怎么走 / 出错怎么办 / 不提供什么 / 相关条目 / 还没定的事。

status: draft · issue #545 · #561 · 字段名是建议值，结构是拍板的

1接口约定 已拍板

三个方法，写分主路径与受限路径。草稿变化走推送。

// ① 读快照
composer.readDraft()
// → { text, marks[], generation }

// ② 插入（主路径）
composer.insertText({ text })
// → { ok: true, generation }

// ③ 整体替换（受限：CAS + 非聚焦 + 非远端）
composer.replaceDraft({ expectedGeneration, text, marks? })
// → { ok: true, generation } 或整次拒绝

字段

字段含义
text输入框当前文字；记号占内部字符
marks[]记号列表（label / 发送策略 / 私有数据 / 位置），按出现顺序
generation草稿世代号；每次草稿变化 +1。replace 时用 expectedGeneration 对账
expectedGeneration只在 replaceDraft 出现：必须等于当前值，对不上整次拒绝

replace 三道闸

闸不过会怎样
① CAS 世代号expectedGeneration ≠ 当前 → 整次拒绝（先到先得，不静默盖别人）
② 输入框非聚焦用户正在输入框里打字 → 拒绝（防吃字）
③ 非远端来源调用来自异步回调 / 网络返回 / 定时器 → 拒绝，改走 insertText

出站分层（公共）

层词约束
核心 Hentry.copy · message.mutate · composer.insertText · attachments.addinsert 是写草稿主路径
核心 Pplugin.call白名单 · ≤64KB · QPS · 2s 超时 · 熔断 · pluginId 宿主注入
核心 FmeasureHeight · deriveSummary同步 16ms · 超时回默认 · F 内禁 H/P
可选 Htoast · ask · clipboard.write · host.open · composer.readDraft · attachments.list/removeclipboard.write 须同次用户手势
拒绝远端来源 replaceDraft · 裸路径附件不得静默改用户数据

2数据怎么走 已拍板

host 输入框 / 草稿登记 slot 方法边界 plugin 插件渲染器
路径方向怎么走
读插件 → 宿主 → 插件readDraft() 同步取一份 { text, marks[], generation } 快照
插插件 → 宿主insertText 在光标处落一段文字；成功后 generation +1
换插件 → 宿主replaceDraft 过三道闸后整体换掉；成功后 generation +1
推宿主 → 插件草稿一变（用户打字、删改、插件写入），rendererData draft 推新快照。不要轮询

递交模型

  • 请求 / 应答：三个方法都是一问一答，返回值立刻落定。
  • 推送：草稿变化是宿主单向推；插件订阅 rendererData draft 即可，不需要也不提供定时拉取。
  • 生命周期：随会话走。切会话后旧快照作废，以新会话的推送为准。
为什么不用轮询。轮询会和推送形成两条来源，插件两边都听就会打架；而且轮询永远晚一拍。拍板：只推不拉。

3出错怎么办 已定

情况结果靠什么保证
generation 对不上replace 整次拒绝；草稿不变CAS 对账
输入框正聚焦replace 整次拒绝非聚焦闸
远端来源调用 replace整次拒绝；应改走 insertText来源闸
text 里丢了宿主锚点记号replace 整次拒绝锚点保护
没有会话整次调用报错，不返回半截快照会话检查
插件被禁用 / 卸载订阅拆除；挂起的写入作废生命周期清理
写入后 0.5s 内没显示整次作废并报错（旧契约，沿用）上屏时限

4不提供什么 已定

不给为什么
轮询读草稿只推不拉；轮询是第二条源
远端来源的 replace会吃掉用户正在打的字
部分写入 / 静默覆盖世代号对不上就整次拒绝
动宿主锚点记号锚点是编辑历史消息的路标
附件读写归 render/attachments/
发送时改写归 runtime/before-send/；本目录只管输入框里的草稿
