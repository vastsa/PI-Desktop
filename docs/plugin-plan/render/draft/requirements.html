草稿读写 · 需求

输入框草稿的读与写：composer.readDraft / composer.replaceDraft / composer.insertText。插入是主路径；整体替换三道闸；草稿变化用推送，不用轮询。

status: draft · issue #545 · #561 · insertText 核心 H · readDraft 可选 H · 远端 replace 拒绝

范围 已定

  • 三个方法，管输入框里的草稿文字和记号：
    • composer.readDraft — 读一份快照
    • composer.insertText — 往光标处插一段文字（主路径）
    • composer.replaceDraft — 整体替换草稿（受限）
  • 草稿变化由宿主推送（rendererData draft），插件不轮询。
  • 不谈：附件三动作（render/attachments/）、输入框界面槽（ui/composer/）、发送前改写（runtime/before-send/）。

契约形状 已拍板

读快照

// 请求：无参数
composer.readDraft()

// 返回
{
  text,                 // 输入框当前文字
  marks: [ … ],         // 记号列表，按出现顺序
  generation            // 草稿世代号；每次草稿变化 +1，给 replaceDraft 对账用
}

插入（主路径）

// 请求：光标处插入一段纯文字
composer.insertText({ text: "请对照 docs/spec/00-baseline.md" })

// 返回
{ ok: true, generation }

整体替换（受限）

// 请求
composer.replaceDraft({
  expectedGeneration,   // 必须等于当前 generation，对不上整次拒绝（CAS）
  text,
  marks?
})

// 返回
{ ok: true, generation }
// 或错误：generation 对不上 / 输入框正聚焦 / 来源是远端 → 整次拒绝
方面内容
readDraft 返回恒 { text, marks[] }（附 generation）
replace 三道闸① CAS expectedGeneration；② 输入框非聚焦才可写；③ 远端来源禁止
insert 地位主路径——远程回来的内容、模板、片段，都走插入
递交草稿变化经 rendererData draft 推送；不要轮询
replace 三道闸（拍板）。整体替换会盖掉用户正在打的字，所以必须同时满足：世代号对得上、输入框此刻没有焦点、调用来源不是远端回调。任何一道不过，整次拒绝，不部分写入。
远端来源禁止 replace（拍板）。「远端来源」指异步回来的结果：插件转发应答、网络请求回调、定时器里迟到的数据。这些场景只能 insertText，不能整体替换——用户可能正在打字，远端迟到的整段替换会把字吃掉。
推送不轮询（拍板）。草稿一变（用户打字、删改、插件写入），宿主经 rendererData draft 推一份新快照。插件订阅即可，不要定时去读。

谁能用 已定

方法谁出站层
composer.insertText插件渲染器（用户手势或本地交互路径）核心 H
composer.readDraft插件渲染器可选 H
composer.replaceDraft插件渲染器，且过三道闸本地过闸后可用；远端来源 → 拒绝

场景 典型用法

#场景用哪条
1常用语 / 模板：点一下，把一段固定文字插到光标处insertText（主路径）
2润色：用户按「润色」，本地算完整段替换；此时输入框非聚焦、世代号对得上replaceDraft（过闸）
3字数 / 进度统计：订阅推送，算完画在自己的按钮上readDraft + 推送
4远程查资料回来往输入框补一句insertText（远端禁止 replace）

明确不做 已定

  • 远端来源禁止 replaceDraft。异步回调、网络返回、定时器迟到数据——一律只能插入。
  • 不提供轮询接口。草稿变化走推送；再提供轮询就是第二条源。
  • 输入框聚焦时不许整体替换。用户正在打字，替换就是吃字。
  • 不做「静默覆盖」。世代号对不上就整次拒绝，不部分写入、不强行盖。
  • 不动宿主自己的记号（例如编辑历史消息时的锚点）：replace 丢掉它 → 整次拒绝。
  • 不给附件读写。那是 render/attachments/；本目录只管草稿文字与记号。
