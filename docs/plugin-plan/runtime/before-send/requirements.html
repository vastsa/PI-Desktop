before-send · 需求

发送路径上的唯一拦截点：用户消息已落库、未进 agent。插件可放行（continue）、改写（transform）、拦截（handled）。改写必须留审计。

status: draft · issue #561 · 权限 runtime.send.before · 风险 high · 三动作 continue / transform / handled

范围 已核实

  • 只管 rpc 发送路径上的一刻：用户消息已持久化、还没进 agent 循环。
  • 不谈：发送按钮与排队提示（输入区的事）、模型请求改写（before-request，已撤回）、审批卡。

现状（代码核实） 已核实

  • 已经在 emit：agent 运行时在发送路径上叫 extensionBeforeSend，事件名 input，权限 runtime.send.before。

  • 三动作：continue / transform / handled。handled 会抛 pluginHandledPromptError，这次发送不进 agent，reason 原样给用户看。
  • 改写留审计：transform 逐条记入 plugin_rewrites（diff 级）；用户消息行保留原文。

  • 信任档：风险 high，装插件时单独确认；refusal 以 permission_denied 报出，不静默。
  • 不写状态检查：契约里没有「没轮在跑 → false」——未核到，不编。
  • 沙箱插件还够不到：沙箱插件的接线通道（ADR 0300）未建——注册、预算、熔断都还没有。
分发机制是现成的。可信扩展运行器统一按权限门控、拒绝已撤回事件、超时按无意见（continue）处理，永不卡死发送。

明确不做 已核实

  • 不让插件改附件（images / attachments 只读）。
  • 不让插件改已落库的用户消息行——原文保留，改写只作用于进 agent 的文本并留审计。
  • 不做发送排队 / 撤回——那是输入区与队列的事。
  • 不写「没轮在跑 → false」这类状态检查（未核到）。
  • 不碰工具参数（与 tool-gate 同一底线：改参数永久排除）。
