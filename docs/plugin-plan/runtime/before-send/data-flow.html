before-send · 数据流

用户按下发送之后、消息进 agent 之前，插件被叫到那一刻发生什么。六节固定：接口约定 / 数据怎么走 / 出错怎么办 / 不提供什么 / 相关条目 / 还没定的事。

status: draft · issue #561 · 权限 runtime.send.before · 风险 high · 三动作 continue / transform / handled

1接口约定 建议

无界面钩子：插件在 agent 侧注册监听，权限 runtime.send.before，风险 high，装时确认。

// 插件 headless 入口注册（建议形态）
pi.on("input", async (payload) => {
  // payload: { sessionId, turnId, text, images, attachments, source: "rpc" }
  if (await hasSecret(payload.text)) {
    return { action: "handled", reason: "检测到疑似密钥，已拦下这次发送" };
  }
  return { action: "continue" };
})
方面内容
输入{ sessionId, turnId, text, images, attachments, source: "rpc" }
输出三动作：continue / transform（带 text）/ handled（带 reason）
顺序多插件按注册顺序链式；改写逐条记 plugin_rewrites
预算30 秒（现值）；超时 = 无意见 = continue
权限runtime.send.before，high，装时确认

一次发送的一生

时刻发生什么
落库用户消息行先持久化（原文）
钩子注册了的插件按序被叫
链上每个插件三选一；transform 改写进入下一个插件并留审计
有人 handled发送被阻断，reason 呈给用户；链中止
全部放行 / 改写完最终文本交给 agent，本轮开始
原文与进 agent 的文本是两份。对话里显示、存储、编辑回填的都是原文；改写只作用于交给模型的那份，且逐条可审计。

3出错怎么办 已核实

情况结果靠什么保证
插件超时按无意见（continue）处理，发送不被卡死30 秒预算
插件抛错该插件本轮无意见 + 诊断记录运行器的拒绝与诊断
handled发送阻断，reason 给用户内核发送路径
无权限permission_denied，不静默叫钩子前权限门控
沙箱插件目前根本收不到ADR 0300 待实现

4不提供什么 已核实

不给为什么
附件的写权images / attachments 只读
消息行的写权原文已落库，属于用户数据；改写仅作用于模型输入并留审计
工具参数改参数永久排除（{ADR_SLOTS_ONCE}）
队列与撤回发送排队、撤回是输入区 / 队列的事
整段对话这里只有这一条草稿；要读历史走 runtime.turn.recap 等接口
状态检查闸门不提供「没轮在跑 → false」——未核到，不写进契约
