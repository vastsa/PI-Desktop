status: draft · 设计稿 · 会话数据契约 · 规划出处：能力清单审查 N4 · 权限 session.compact.write（新增） · 尚无 SDK 实现

1用途与边界

把插件算好的压缩摘要交宿主托管写回：宿主校验后写入压缩记录（挂现有 session.appendCompaction 链），界面显示压缩行，下一轮对话生效。插件永远不直接改消息列表。

pi.session.applyCompaction(input: { sessionId: string; summary: string; retainedMessageIds?: string[]; reason?: string }): Promise<PluginApplyCompactionResult>

权限：session.compact.write（新增 · high · 装时确认 · 操作界面可见可审计）。

2典型场景

场景插件做什么
DIY 压缩器（主场景）用 session.getContext 读工作集 → 自算摘要（如 agent.complete）→ 提交本接口写回。
领域压缩按领域知识压缩（代码讨论保代码块、长文档保结论），比通用摘要更省 token。
用户手动触发插件面板放「立即压缩」按钮，用户主动瘦身话话。

3明确不做什么

不做静默改写：不提供 replaceMessages，摘要必须进压缩记录、界面可见、带来源戳。不做撤销/回滚（v1；压缩行可见可审计，回滚留后续版本）。summary 只收纯文本。
