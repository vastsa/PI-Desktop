session-lifecycle · 需求

会话生命周期五种时刻。只有压缩前（before_compact）可否决；其余全是通知。

status: draft · issue #561 · 权限 runtime.session.lifecycle · 仅 before_compact 可否决

范围 已核实

  • 只管会话级时刻：创建、删除、切换、分叉、压缩。
  • 不谈：轮内事件（turn-watch）、读写消息（turn-recap / 其他接口）。

现状（代码核实） 已核实

  • 槽已注册并门控：runtime.session.lifecycle。
    feat/528-plugin-slots@ · packages/shared/src/trusted-extensions.ts · runtime.session.lifecycle
  • 事件从三处来：create / delete 由桌面发出，switch / fork 由桌面转发，compact 由 sidecar 自发。
    feat/528-plugin-slots@ · apps/desktop/electron/ipc/session-ipc.ts · session 生命周期 emit
    feat/528-plugin-slots@ · packages/agent-runtime/src/runtime.ts · session_compact / session_before_compact
  • before_compact 载荷（必须按此写）：{ type, reason, retentionMode, segment: { messages, messageCount, tokensBefore, retained } }；可返回 { cancel?: boolean }；仅压缩前可否决。
  • 通知默认不等待：除 before_compact 外全部通知式，不等插件、不可拦。
  • 沙箱缺口：沙箱插件的接线通道（ADR 0300）未建——注册、预算、熔断都还没有。
否决权只给压缩。切会话、fork、删除都是用户的直接操作——插件只能跟着知道，不能拦。压缩是后台自动行为，给插件一次「先别压，我还要读」的机会。

完整载荷写死。before_compact 不是只给 segment——外层还有 type, reason, retentionMode；可返回 { cancel?: boolean }；仅压缩前可否决。

插件场景 建议

#场景动作
1切换留痕：记录用户何时换会话before_switch 通知
2压缩保护：before_compact 发现段里有未处理内容 → { cancel: true }，先处理完再说before_compact 否决
3删除备份：deleted 时把插件自己的索引标脏deleted 通知

明确不做 已核实

  • 不让插件否决切换 / fork / 删除——用户直接操作不可拦。
  • 不让通知事件等待插件——除 before_compact 外全部通知式。
  • 不让插件改写压缩段内容——只能取消这一次压缩，不能改 messages。
  • 不让插件改 retention 策略本身——retentionMode 只读。
