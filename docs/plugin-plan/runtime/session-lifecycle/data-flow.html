1接口约定 建议

无界面事件监听，runtime.session.lifecycle。除 before_compact 外全部通知式。

// 仅压缩前可否决
pi.on("session_before_compact", (payload) => {
  // payload: { type, reason, retentionMode,
  //           segment: { messages, messageCount, tokensBefore, retained } }
  if (needMoreTime(payload.segment)) {
    return { cancel: true };
  }
  return {}; // 或 { cancel: false } / 不返回
});
方面内容
before_compact 输入{ type, reason, retentionMode, segment: { messages, messageCount, tokensBefore, retained } }
before_compact 输出{ cancel?: boolean }——仅压缩前可否决
其余时刻通知式：不等待、不可拦、返回值忽略

before_compact 的一生

时刻发生什么
压缩将启sidecar 发出 before_compact，载荷含 type, reason, retentionMode, segment
插件读 segment；可返回 { cancel?: boolean }
cancel: true这一次压缩取消；内容保留
不取消 / 超时压缩继续；随后 compact 或 compact_failed 通知
仅压缩前可否决。切会话、fork、删除都不接受 cancel。

3出错怎么办 已核实

情况结果靠什么保证
before_compact 超时按不取消处理，压缩继续结果性预算
返回 cancel: true这一次压缩取消唯一否决点
通知事件抛错记诊断，会话操作照常通知式隔离
试图 cancel 切换 / 删除不支持——忽略仅压缩前可否决
沙箱插件目前收不到ADR 0300

4不提供什么 已核实

不给为什么
切换 / fork / 删除的否决用户直接操作不可拦；仅压缩前可否决
改写压缩段只能取消这一次，不能改 messages
改 retention 策略retentionMode 只读
通知回执通知式，不等待
