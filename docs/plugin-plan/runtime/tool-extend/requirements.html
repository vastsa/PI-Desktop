tool-extend · 需求

插件自有工具的返回值上，可以带三个可选字段。宿主按权限决定收下还是剥掉。

status: draft · issue #561 · 权限 runtime.tool.extend · addedToolNames / usage / terminate

范围 已核实

  • 只管插件自有工具返回值上的三个可选字段。
  • 不谈：宿主内建工具的拦截（tool-gate）、发送路径（before-send）。

现状（代码核实） 已核实

  • 三字段已在契约里：addedToolNames / usage / terminate，按 runtime.tool.extend 授权收下或剥掉。
    feat/528-plugin-slots@ · packages/agent-runtime/src/runtime.ts · addedToolNames / usage / terminate
    feat/528-plugin-slots@ · packages/shared/src/trusted-extensions.ts · runtime.tool.extend
  • 没授权 → 剥离 + 审计，不是静默丢弃、也不是整单失败。
  • 引入的工具在界面上署名插件作者。
  • 沙箱缺口：沙箱插件的接线通道（ADR 0300）未建——注册、预算、熔断都还没有。

契约（建议） 建议

字段含义没授权时
addedToolNames本次调用往循环里引入新工具（下一轮模型可用）剥离 + 审计；工具不注册
usage报告花费（供宿主记账 / 展示）剥离 + 审计
terminate请求批量终止（例如批处理提前收工）剥离 + 审计；不终止
引入的工具署名插件作者。用户在界面上看得见是谁加的工具；受授权门控。

插件场景 建议

#场景动作
1工具链：一次调用里顺手注册「下一步」专用工具addedToolNames
2自定义计费：插件工具真调了外部 API，报告花费usage
3批处理收工：发现目标已完成，请求终止剩余项terminate

本轮拍板 待定

问题选项
usage 汇总口径A. 插件自报原样展示　B. 归一到宿主的用量体系
terminate 提示A. 静默收工　B. 对话里一行「由插件 X 请求终止」

明确不做 已核实

  • 不让无授权插件靠这三个字段提权——没权限就是剥掉。
  • 不让 addedToolNames 注册与内建工具同名的工具（覆盖宿主）。
  • 不改宿主工具的结果——那是 tool-gate 的只读边界。
  • terminate 不等于 abort-turn 的整轮中止语义（范围不同）。

还没定的事 未定

  • usage 口径、terminate 提示形态。
  • 沙箱插件的接线通道（ADR 0300）未建——注册、预算、熔断都还没有。
