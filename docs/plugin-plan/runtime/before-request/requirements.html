before-request · 需求

模型请求层改写已撤回。本页维持撤回决定，并给出场景迁移表：原来想做的事各有更合适的去处。

status: draft · issue #561 · 权限 runtime.request.before · 已撤回 · 不作为正选项重开 message_list 改写

范围 已核实

  • 范围：曾经的「模型请求发出前改写请求体」这一档能力——现已撤回。
  • 本页只做两件事：确认维持撤回；给出场景迁移表。
  • 不谈：怎么实现改写、怎么重开、message_list 怎么编辑。

现状（代码核实） 已核实

  • 撤回是产品决定：ADR 0303（原 0295） 记录了「决定并随后收回」，不是实现没跟上。
  • 内核事件映射不开放：runtime.request.before 在权限清单里标为已撤回，可信运行器会拒绝该事件。
  • 重开不排期：本轮不把「可重开 message_list 改写」写成正选项。
  • 沙箱缺口：沙箱插件的接线通道（ADR 0300）未建——注册、预算、熔断都还没有。与本页关系不大——本页本身已撤回。

契约（建议） 建议

维持撤回。下表是场景迁移对照（建议按此分流，不再走 before-request）。

原来想在 before-request 做的事现在去哪
prompt 注入 / 组装inject / compose（会话提示词装配）
历史治理（裁剪、摘要、排序）宿主压缩（compaction），不要插件改写请求体
model / think 覆盖会话绑定（session 绑定的模型与思考档）
出站内容拦截 / 改写before-send（发送路径，带审计）
取消这次请求abort-turn（中止本轮）
不写「可重开 message_list 改写」为正选项。改写模型要看到的全部历史，风险高于发送层改写一个数量级；即便将来重开，也必须先有 diff 级审计与短预算，且单独拍板。

明确不做 已核实

  • 不让插件改写模型请求体（message_list、工具列表、系统提示）。
  • 不把「重开 message_list 改写」写成正选项。
  • 不做静默改写——任何改写都必须可审计、用户可感知；当前选择是干脆不开。
  • 不在本目录设计实现细节。
