turn-closing · 需求

轮末被动询问：插件可以建议再续几轮。续跑经 agent.steer({role:"user"}) 注入——无插件署名，这是缺陷，不得写成「署名可见」。

status: draft · issue #561 · 权限 runtime.turn.closing · 续跑走 agent.steer · 缺插件署名（缺陷）

范围 已核实

  • 只管「轮末收束前的被动询问」：插件可建议续跑。
  • 不谈：插件主动续跑（turn-continue）、实时观察（turn-watch）、中止（abort-turn）。
  • 必须写明：续跑路径缺署名——这是缺陷，不是特性。

现状（代码核实） 已核实

  • 预算已在：每次运行最多续若干轮（现值 4），续跑默认注入一条消息，经 agent.steer({role:"user"}) 进循环。
    feat/528-plugin-slots@ · packages/agent-runtime/src/extensions/turn-closing.ts · 续跑预算 / 默认注入
    feat/528-plugin-slots@ · packages/agent-runtime/src/runtime.ts · agent.steer 续跑
  • 续跑路径缺插件署名（缺陷）：agent.steer({role:"user"}) 注入的消息不带 pluginId / pluginLabel——用户看不出这是插件让跑的。对照：turn-continue → queuePush 会补署名。两者不一致。
  • 已 emit、消费者少：事件已接；SDK 类型化载荷仍薄。
  • 沙箱缺口：沙箱插件的接线通道（ADR 0300）未建——注册、预算、熔断都还没有。
缺陷：续跑路径缺署名。不是「署名可见」。steer 注入的 user 消息没有插件名；有署名的是 turn-continue 的 queuePush。收口方式见拍板。

明确不做 已核实

  • 不把无署名续跑写成「署名可见」——那是缺陷描述，不是能力描述。
  • 不让插件改对话记录或伪造轮次——续跑经 agent.steer 走正常循环，行是宿主记的（但目前缺插件名）。
  • 不做无限续跑——有预算。
  • 不在轮末给插件写权限。
