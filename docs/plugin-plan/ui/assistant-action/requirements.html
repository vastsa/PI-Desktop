AI 回复操作栏 · 需求

AI 回复卡操作栏两侧的新增位。与用户消息操作栏同形、同约束。

status: finalized · 本轮拍板见文末

范围 已定

只管 AI 回复消息卡操作栏的左右两侧。正文下方的追加块归 ui/entry-extra/。

槽形状 已定

固定布局：【左插槽】宿主键【右插槽】。宿主键永远在中间，只许插件新增。
位置语义
左插槽宿主键左侧新增区，可放 0..n 个插件内容
右插槽宿主键右侧新增区，可放 0..n 个插件内容

插件能拿到什么 已定

  • message — 这条 AI 回复的数据
  • 各种 id — 消息 id、会话 id 等
  • position — "left" | "right"
  • 不提供宿主函数与额外数据

插件场景 已定

场景装上插件之后
存为知识库右插槽一颗按钮，点击后插件自己去存
一键复现左插槽按钮，把这条回复交给插件自己的流程

插件自实现的功能（含删除）宿主不额外处理。

明确不做 已定

  • 不改 / 不藏 / 不删宿主键
  • 不改回复正文（entry 正文不开放、无整卡替换）
  • 不提供宿主函数与额外数据
  • 正文下方追加块不在本槽（见 ui/entry-extra/）
  • markdown transformer 不做

本轮拍板 已定

问题决定
槽形状【左插槽】宿主键【右插槽】，与用户卡同形，只许新增
props只有 message + 各种 id + position；不提供函数、不提供额外数据
宿主键可否被改 / 藏 / 删不可
正文 / 整卡替换不做
插件自实现功能（含删除）宿主不额外处理
定稿：SDK 槽名 assistantAction（与 userAction 同形，注册形状 positions?: ["left","right"]，省略即两侧）；左右上限与折叠规则与 user-action 完全一致：每侧 3 个可见项 + 宿主「⋯」折叠菜单，宿主键永不折叠。
