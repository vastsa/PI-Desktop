1接口约定

pi.desktop.invoke(input: PluginDesktopInvokeInput): Promise<unknown>

让宿主代为执行一条已审查目录中的桌面操作（与本地 MCP 控制平面同一份目录）；权限 —。

入参

字段类型必填说明
operationstring是操作 id，来自 desktop.listOperations 的目录。
argsunknown[]否操作的位置参数，形状随各操作的定义。
confirmboolean否插件侧确认位；dangerous 操作要求置 true，缺省视为未确认。

出参

字段类型说明
（返回值）unknown操作结果，形状由被调用的操作定义。

输入样例

{ "operation": "session/delete", "args": ["s_01"], "confirm": true }

输出样例

// 返回类型为 unknown，形状由被调用的操作决定，此为示意
{ "deleted": true, "sessionId": "s_01" }
一句话边界。白名单代办：只执行已审查目录里的操作，不开放任意 IPC；审计只记操作 id 与结果，参数值不进审计正文。

2数据怎么走

  1. 调用。插件以操作 id 与位置参数发起代办（目录可先经 desktop.listOperations 获取）。
  2. 校验。宿主在已审查目录中查找操作：未知名 NOT_FOUND，参数不符 INVALID_ARGUMENT，未授权 PERMISSION_DENIED。
  3. 确认。dangerous 操作需双重确认：插件 confirm: true，且用户在原生对话框应答；对话框点名操作 id，不显示插件/模型撰写的文本；缺确认返回 CONFIRMATION_REQUIRED。
  4. 执行。宿主代为执行并把结果返回插件。
  5. 审计。事后审计只记操作 id 与结果，参数值不进审计正文。
方向内容
插件 → 宿主操作 id、位置参数、插件确认位。
宿主 → 用户dangerous 操作的原生确认对话框（点名操作 id）。
宿主 → 插件操作结果（形状随操作）。

3出错怎么办

情况结果码
插件未获该操作的授权调用被拒PERMISSION_DENIED
dangerous 操作缺插件 confirm: true，或用户未在原生对话框应答不执行，要求补确认CONFIRMATION_REQUIRED
操作 id 不在已审查目录中调用被拒NOT_FOUND
位置参数与操作定义不符调用被拒INVALID_ARGUMENT

4不提供什么

不开放任意 IPC；参数值不进审计正文。

宿主保证 / 已接受代价：宿主保证：被提示注入的转录本无法把危险操作改写成无害文案。已接受代价：参数值不进审计，事后只能看到操作 id 与结果。
