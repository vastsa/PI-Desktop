1接口约定

pi.audio.openInput(options?: PluginAudioOpenInputOptions): Promise<PluginAudioInputSession>

打开一条后台麦克风采集流并返回会话元数据（权限：—）。

入参

入参为可选对象 PluginAudioOpenInputOptions，可整体省略（省略即系统默认输入）。

字段类型必填说明
deviceIdstring否来自 getInputDevices 的设备 id；省略表示系统默认输入。
sampleRatenumber否期望采样率。
channelsnumber否声道数。
echoCancellationboolean否回声消除。
noiseSuppressionboolean否噪声抑制。
autoGainControlboolean否自动增益。

出参

字段类型说明
streamIdstring会话 id；closeInput 用它关闭，帧事件中的 streamId 与之对应。
sampleRatenumber实际生效的采样率。
channelsnumber实际生效的声道数。
deviceIdstring可选；实际打开的设备 id。
labelstring可选；实际打开的设备显示名。

输入样例

{ "deviceId": "", "sampleRate": 16000, "channels": 1, "echoCancellation": true }

输出样例

{ "streamId": "in-3f9a2c", "sampleRate": 16000, "channels": 1, "label": "默认 - 麦克风 (Realtek Audio)" }
一句话边界。每个插件同时只有一条输入流；拿到的是会话元数据，不是 MediaStream，也不暴露操作系统设备路径。

2数据怎么走

  1. 调用：pi.audio.openInput(options?)，参数可整体省略。
  2. 校验：宿主核对权限（未授权 PERMISSION_DENIED）与参数合法性（INVALID_ARGUMENT）。
  3. 执行：宿主打开设备并替插件持有它；每个插件同时只允许一条输入流。
  4. 返回：resolve 会话 { streamId, sampleRate, channels, deviceId?, label? }；帧随后经 onInputFrame 到达。
  5. 生命周期：插件禁用 / 卸载 / 崩溃时，宿主立即停止该采集。
方向内容
插件 → 宿主打开请求（设备 id、采样率 / 声道数、回声消除 / 降噪 / 自动增益偏好）。
宿主 → 插件会话元数据（streamId 与实际生效参数）。
宿主 → 系统打开选定的系统输入设备。

3出错怎么办

情况结果码
插件未获音频采集权限调用失败（reject）PERMISSION_DENIED
宿主无音频后端调用失败（reject）UNSUPPORTED
入参不合法调用失败（reject）INVALID_ARGUMENT

4不提供什么

不给 MediaStream；不给操作系统设备路径。
