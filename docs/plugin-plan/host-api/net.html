net.fetchimplemented

status: implemented · 事实源 packages/plugin-sdk/src/index.ts · PluginHostApi

1接口约定

pi.net.fetch(input: { url: string; method?: string; headers?: Record<string, string>; body?: string; timeoutMs?: number }): Promise<{ status: number; headers: Record<string, string>; bodyText: string }>

宿主代发一次 HTTP 请求并返回完整响应（权限：—；出网受 manifest.net.domains 白名单约束）。

入参

字段类型必填说明
urlstring是目标地址；仅 http / https，主机必须命中 manifest.net.domains。
methodstring否HTTP 方法，如 "GET" / "POST"。
headersRecord<string, string>否请求头键值对，值必须是字符串。
bodystring否请求体文本（如序列化后的 JSON），没有二进制请求体。
timeoutMsnumber否超时毫秒数；到点未完成按 TIMEOUT 失败。

出参

字段类型说明
statusnumberHTTP 状态码。
headersRecord<string, string>响应头键值对。
bodyTextstring响应体文本；只提供文本形式，没有二进制响应体。

输入样例

{ "url": "https://api.example.com/v1/notes", "method": "POST", "headers": { "Content-Type": "application/json" }, "body": "{\"title\":\"会议纪要\"}", "timeoutMs": 10000 }

输出样例

{ "status": 200, "headers": { "content-type": "application/json" }, "bodyText": "{\"ok\":true,\"id\":42}" }
一句话边界。只出 manifest.net.domains 声明过的主机；域列表为空即完全不能出网，也不暴露宿主代理密钥。

2数据怎么走

  1. 调用：插件进程传入 { url, method?, headers?, body?, timeoutMs? }。
  2. 校验：URL 仅 http / https；主机名必须命中 manifest.net.domains（条目是裸主机名或 *.后缀，不收端口 / 路径 / 裸 *），否则按 PERMISSION_DENIED 拒绝。
  3. 执行：宿主代为发出请求；timeoutMs 到点未完成即失败。
  4. 返回：{ status, headers, bodyText } 一次给全；无流式响应、无进度回调。
方向内容
插件 → 宿主请求描述（url、方法、头、体、超时）。
宿主 → 系统向白名单主机发出真实 HTTP 请求。
宿主 → 插件{ status, headers, bodyText }。

3出错怎么办

情况结果码
目标主机不在 manifest.net.domainsPromise 拒绝，请求不发出PERMISSION_DENIED
timeoutMs 内未完成Promise 拒绝TIMEOUT
参数不合法（如 URL 无法解析）Promise 拒绝，请求不发出INVALID_ARGUMENT

4不提供什么

域列表为空即完全不放行出网；不暴露宿主代理密钥。

宿主保证 / 已接受代价：宿主保证：出不了声明域名。已接受代价：没有声明域名就完全不能出网。

net.websocket.closeimplemented

status: implemented · 事实源 packages/plugin-sdk/src/index.ts · PluginHostApi

1接口约定

pi.net.websocket.close(input: { socketId: string; code?: number; reason?: string }): Promise<void>

主动关闭一个已连接的套接字（权限：—；不携带业务数据，业务数据走 net.websocket.send）。

入参

字段类型必填说明
socketIdstring是net.websocket.connect 返回的连接句柄。
codenumber否WebSocket 关闭码。
reasonstring否关闭原因文本。

出参

字段类型说明
（返回值）void无返回数据，成功即 resolve。

输入样例

{ "socketId": "ws-a1b2c3", "code": 1000, "reason": "面板已关闭" }

输出样例

// void —— 成功即 resolve，无输出
一句话边界。只做关闭握手，没有 data 字段；插件卸载时未关的套接字由宿主代关。

2数据怎么走

  1. 调用：插件进程传入 { socketId, code?, reason? }。
  2. 校验：socketId 必须是本插件仍持有的连接。
  3. 执行：宿主立即发起关闭并释放连接；关闭结果经 close 事件回告（PluginWebSocketCloseEvent：socketId / code / reason / wasClean）。
  4. 返回：无回执值。
方向内容
插件 → 宿主socketId + 可选关闭码 / 原因。
宿主 → 系统向对端发出 WebSocket 关闭握手。
宿主 → 插件PluginWebSocketCloseEvent（socketId / code / reason / wasClean）。

3出错怎么办

情况结果码
socketId 不存在或已关闭Promise 拒绝，连接保持原状NOT_FOUND
参数不合法（如 code / reason 类型错误）Promise 拒绝INVALID_ARGUMENT

4不提供什么

不发送业务数据（业务数据走 send）。

net.websocket.connectimplemented

status: implemented · 事实源 packages/plugin-sdk/src/index.ts · PluginHostApi

1接口约定

pi.net.websocket.connect(input: PluginWebSocketConnectInput): Promise<{ socketId: string }>

连接 ws:// / wss:// 端点并返回套接字句柄（权限：—；域名约束与 net.fetch 同一套 manifest.net.domains）。

入参

字段类型必填说明
urlstring是绝对 ws:// / wss:// 地址；主机必须在 manifest.net.domains。
headersRecord<string, string>否握手请求头键值对。
protocolsstring[]否WebSocket 子协议列表。
timeoutMsnumber否握手超时毫秒数。

出参

字段类型说明
socketIdstring新连接的句柄；后续 send / close 与 open / message / close / error 事件都用它标识。

输入样例

{ "url": "wss://rt.example.com/feed", "protocols": ["v1.json"], "timeoutMs": 5000 }

输出样例

{ "socketId": "ws-a1b2c3" }
一句话边界。域外主机到不了传输层，不给原生 socket 句柄；每插件最多 4 个连接，帧封顶 1 MiB，插件卸载时宿主全部关闭。

2数据怎么走

  1. 调用：插件进程传入 { url, headers?, protocols?, timeoutMs? }。
  2. 校验：仅接受 ws:// / wss://，主机名必须命中 manifest.net.domains（与 net.fetch 同一 allowlist），否则 PERMISSION_DENIED；ws:// 只是 http 的明文形态，不构成更宽松通道。
  3. 执行：宿主建立并持有底层套接字（每插件上限 4 个），插件只拿到 socketId。
  4. 后续：打开与消息经事件送达（PluginWebSocketOpenEvent / PluginWebSocketMessageEvent）；插件卸载 / 禁用 / 崩溃时宿主关闭其全部套接字。
方向内容
插件 → 宿主连接描述（url、握手头、子协议、超时）。
宿主 → 系统向白名单主机发起 WebSocket 握手并持有连接。
宿主 → 插件{ socketId }；之后 open / message / close / error 事件。

3出错怎么办

情况结果码
主机不在 manifest.net.domainsPromise 拒绝，不发起连接PERMISSION_DENIED
已达每插件 4 个套接字上限Promise 拒绝LIMIT_EXCEEDED
握手超时Promise 拒绝TIMEOUT
连接建立失败Promise 拒绝CONNECT_FAILED
宿主找不到对应套接字记录Promise 拒绝NOT_FOUND
参数不合法（如 url 缺失或非 ws/wss）Promise 拒绝INVALID_ARGUMENT

4不提供什么

域外主机到不了传输层；不给原生 socket 句柄；帧封顶 1 MiB。

宿主保证 / 已接受代价：宿主保证：插件卸载时套接字必关。已接受代价：最多 4 个连接，帧 1 MiB 封顶。

net.websocket.sendimplemented

status: implemented · 事实源 packages/plugin-sdk/src/index.ts · PluginHostApi

1接口约定

pi.net.websocket.send(input: { socketId: string; data: string | Uint8Array }): Promise<void>

向已连接的套接字发送一帧文本或二进制数据（权限：—）。

入参

字段类型必填说明
socketIdstring是net.websocket.connect 返回的连接句柄。
datastring | Uint8Array是帧内容：文本帧传 string，二进制帧传 Uint8Array；单帧封顶 1 MiB。

出参

字段类型说明
（返回值）void无返回数据，成功即 resolve。

输入样例

{ "socketId": "ws-a1b2c3", "data": "{\"type\":\"ping\"}" }

输出样例

// void —— 成功即 resolve，无输出
一句话边界。整帧发送，不接受分片续传；帧过大按 LIMIT_EXCEEDED 拒绝。

2数据怎么走

  1. 调用：插件进程传入 { socketId, data }。
  2. 校验：socketId 必须是本插件仍持有的连接；帧大小超过 1 MiB 上限拒绝。
  3. 执行：宿主把这一帧写出到对端；string 与 Uint8Array 都按单帧发出。
  4. 返回：无回执值；对端的响应走 message 事件回来。
方向内容
插件 → 宿主socketId + 一帧数据。
宿主 → 系统向对端写出 WebSocket 帧。

3出错怎么办

情况结果码
socketId 不存在或已关闭Promise 拒绝，帧不发出NOT_FOUND
帧超过 1 MiB 上限Promise 拒绝LIMIT_EXCEEDED
参数不合法（如 data 既非 string 也非 Uint8Array）Promise 拒绝INVALID_ARGUMENT

4不提供什么

不接受分片续传语义。
