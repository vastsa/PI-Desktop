1接口约定

pi.services.register(service: PluginService): void

登记常驻后台服务；id 须先在清单 contributes.services 声明，同步本地登记，宿主决定何时 start。权限：—。

入参

字段类型必填说明
idstring是必须匹配 contributes.services[].id，注销时用它寻址。
start(ctx: PluginServiceContext) => Promise<void> | void是宿主启动服务时回调；ctx.log(msg) 往插件宿主日志追加一行。
stop() => Promise<void> | void否宿主停止服务时回调。

出参

字段类型说明
（返回值）void同步返回，仅本地登记，不等待启动。

输入样例

pi.services.register({
  id: "sync-daemon",
  start: async (ctx) => { ctx.log("sync-daemon started"); },
  stop: async () => { /* 释放句柄 */ },
});

输出样例

// 无返回值（同步 void）
一句话边界。登记不等于自动启动——宿主决定何时 start；服务受后退监督，进程异常退出按清单 autoRestart（默认 true）重启。

2数据怎么走

  1. 插件同步交出服务对象，id 必须已在 contributes.services 声明。
  2. 校验：未声明的 id 拒绝（INVALID_ARGUMENT）；未获后台服务权限拒绝（PERMISSION_DENIED）。
  3. 宿主完成本地登记，何时调 start 由宿主决定。
  4. 插件卸载/禁用时宿主先 stop 再清理登记。
方向内容
插件 → 宿主服务对象（id、start、stop? 回调）。
宿主 → 插件按 start / stop 生命周期回调（ctx.log 写宿主日志）。

3出错怎么办

情况结果码
未获后台服务权限同步抛出，登记不生效PERMISSION_DENIED
id 未在 contributes.services 声明同步抛出，登记不生效INVALID_ARGUMENT

4不提供什么

本地登记不等于自动启动；受后退监督。
