1接口约定

pi.usage.listTurns(input?: { fromMs?: number; toMs?: number; projectId?: number | null; sessionId?: string; cursor?: string; limit?: number }): Promise<PluginUsageTurnPage>

分页读取已完成 turn 的用量事实行（token 计数与标识，只读，无消息正文）。权限：—。

入参

字段类型必填说明
fromMsnumber否窗口起点，epoch ms（含）；默认 toMs − 30 天。
toMsnumber否窗口终点，epoch ms（含）；默认 now；窗口跨度 ≤ 365 天。
projectIdnumber | null否只看某一个持久项目。
sessionIdstring否只看某一个会话。
cursorstring否上一页返回的 nextCursor（不透明，原样传回）。
limitnumber否每页行数，1..=500；默认 200。

出参

字段类型说明
turnsPluginUsageTurn[]按 endedAt 升序。数组元素结构：turnId、sessionId、sessionTitle（string|null）、projectId（number|null）、providerId（string|null）、modelId（string|null）、startedAt、endedAt（epoch ms）、inputTokens、outputTokens、cacheReadTokens、cacheWriteTokens、reasoningTokens。
nextCursorstring | null下一页游标；null 表示窗口已取完。

输入样例

{ "fromMs": 1770000000000, "toMs": 1772592000000, "limit": 100 }

输出样例

2数据怎么走

  1. 调用：插件给窗口（fromMs / toMs）、过滤（projectId / sessionId）、cursor、limit。
  2. 校验：需 usage.read 权限；窗口跨度 ≤ 365 天、limit 1..=500，否则 INVALID_ARGUMENT。
  3. 执行：宿主从用量事实表（turns.usage_json）做 keyset 分页，按 endedAt 升序。
  4. 返回：turns + nextCursor；游标为 null 即取完。
方向内容
插件 → 宿主窗口 / 过滤 / 分页参数。
宿主 → 插件用量事实行页 { turns, nextCursor }。
推荐姿势（能力清单 N2 已结案：不新增推送接口）。事件在用量落库之后才广播（主进程先 await session.endTurn 写库提交、后广播 session:turnEnded），因此监听 session:turnEnded 当信号、再用游标增量拉取本接口即准确：事件丢失可全量补拉，数字与宿主用量页同源。
宿主链路（官方 RPC）。轮内累计 usage → 轮结束 RPC session.endTurn → host-core 事务写 turns 表 → 广播 session:turnEnded；读取侧：插件 usage.listTurns → 主进程校验 usage.read → plugin.usage.listTurns → host-core plugin_usage::list_turns_page → SQLite turns（keyset：ended_at, id 升序）。

3出错怎么办

情况结果码
