1接口约定

按 glob 模式列出规则根内匹配的根相对路径。权限：—

入参

字段类型必填说明
patternstring是根相对 glob（如 **/*.ts）；没有 pathFromRoot 参数。

出参

字段类型说明
（返回值）string[]匹配的根相对路径，可直接用于 fs.readText / fs.stat。

输入样例

const files = await pi.fs.glob("**/*.test.ts");

输出样例

["src/fs.test.ts", "src/policy.test.ts"]
一句话边界。只给路径不给正文；结果不是目录树导航，逐层看用 fs.list。

2数据怎么走

  1. 调用：插件传一个根相对 glob 模式（无 pathFromRoot 参数，作用域就是规则根）。
  2. 匹配：模式与 manifest.fs scope 共用同一套语义 —— ** 跨目录段，*/? 只在单段内；含 .. 的路径永不匹配；Windows/macOS 上忽略大小写。
  3. 过滤：结果只保留声明读范围允许、且未命中拒绝列表（.git、.env 等）的路径。
  4. 返回：匹配的根相对路径数组回给插件。
方向内容
插件 → 宿主glob 模式。
宿主 → 插件匹配的根相对路径数组。

情况结果码
缺少 fs.read拒绝PERMISSION_DENIED
模式不是合法的根相对 glob拒绝INVALID_ARGUMENT
匹配结果超过宿主允许的上限拒绝LIMIT_EXCEEDED

4不提供什么

不读正文；结果不是目录树导航（用 fs.list）。

1接口约定

pi.fs.writeText(pathFromRoot: string, content: string): Promise<void>

把文本新建或覆盖写入规则根下的路径。权限：—（写入受 fs.write 与声明写范围约束）

入参

字段类型必填说明
pathFromRootstring是规则根下的相对路径（正斜杠、无前导 /，不接受 ..）；必须落在 manifest.fs 声明的写范围内，写范围不允许覆盖整棵根。
contentstring是要写入的完整文本，整体覆盖，无追加模式。

出参

字段类型说明
（返回值）void无返回数据；Promise resolve 即写入完成。

输入样例

await pi.fs.writeText("reports/周报.md", "# 周报\n\n本周完成插件沙箱梳理。");

输出样例

// 无返回（void）；resolve 即写入成功
一句话边界。无追加模式，改大文件要整段重写；不写二进制；整棵树的写范围过不了校验。

2数据怎么走

  1. 调用：插件传根相对路径与全文。
  2. 校验：须有 fs.write；路径规范化后不得含 ..、不得命中拒绝列表，且必须落在声明写范围内（写范围不得为整棵根，manifest 校验阶段就拒绝）。
  3. 执行：宿主在范围内新建或覆盖该文件，写入文本内容。
  4. 返回：resolve 即完成，无数据。
方向内容
插件 → 宿主根相对路径 + 文本全文。
宿主 → 插件无数据（仅成功/失败）。
宿主 → 系统落盘写入工作区（或 userSelected 根）下的文件。
