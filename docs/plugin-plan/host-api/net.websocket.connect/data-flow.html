1接口约定

pi.net.websocket.connect(input: PluginWebSocketConnectInput): Promise<{ socketId: string }>

连接 ws:// / wss:// 端点并返回套接字句柄（权限：—；域名约束与 net.fetch 同一套 manifest.net.domains）。

入参

字段类型必填说明
urlstring是绝对 ws:// / wss:// 地址；主机必须在 manifest.net.domains。
headersRecord<string, string>否握手请求头键值对。
protocolsstring[]否WebSocket 子协议列表。
timeoutMsnumber否握手超时毫秒数。

出参

字段类型说明
socketIdstring新连接的句柄；后续 send / close 与 open / message / close / error 事件都用它标识。

输入样例

{ "url": "wss://rt.example.com/feed", "protocols": ["v1.json"], "timeoutMs": 5000 }

输出样例

{ "socketId": "ws-a1b2c3" }
一句话边界。域外主机到不了传输层，不给原生 socket 句柄；每插件最多 4 个连接，帧封顶 1 MiB，插件卸载时宿主全部关闭。

2数据怎么走

  1. 调用：插件进程传入 { url, headers?, protocols?, timeoutMs? }。
  2. 校验：仅接受 ws:// / wss://，主机名必须命中 manifest.net.domains（与 net.fetch 同一 allowlist），否则 PERMISSION_DENIED；ws:// 只是 http 的明文形态，不构成更宽松通道。
  3. 执行：宿主建立并持有底层套接字（每插件上限 4 个），插件只拿到 socketId。
  4. 后续：打开与消息经事件送达（PluginWebSocketOpenEvent / PluginWebSocketMessageEvent）；插件卸载 / 禁用 / 崩溃时宿主关闭其全部套接字。
方向内容
插件 → 宿主连接描述（url、握手头、子协议、超时）。
宿主 → 系统向白名单主机发起 WebSocket 握手并持有连接。
宿主 → 插件{ socketId }；之后 open / message / close / error 事件。

3出错怎么办

情况结果码
主机不在 manifest.net.domainsPromise 拒绝，不发起连接PERMISSION_DENIED
已达每插件 4 个套接字上限Promise 拒绝LIMIT_EXCEEDED
握手超时Promise 拒绝TIMEOUT
连接建立失败Promise 拒绝CONNECT_FAILED
宿主找不到对应套接字记录Promise 拒绝NOT_FOUND
参数不合法（如 url 缺失或非 ws/wss）Promise 拒绝INVALID_ARGUMENT

4不提供什么

域外主机到不了传输层；不给原生 socket 句柄；帧封顶 1 MiB。

宿主保证 / 已接受代价：宿主保证：插件卸载时套接字必关。已接受代价：最多 4 个连接，帧 1 MiB 封顶。
