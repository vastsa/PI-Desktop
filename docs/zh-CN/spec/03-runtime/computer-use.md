# 电脑操作 v1

> **翻译说明：** 本页与[英文源规格](/spec/03-runtime/computer-use)一一对应。代码、协议字段和标识符保留原文；如翻译与英文源事实存在差异，以英文版本为准。

> 状态：设计已接受，尚未实现。本页是 [ADR 0340](../../../adr/0340-os-computer-use-capability.md) 所述能力的权威契约，仓库中目前没有任何代码实现它。

## 范围

电脑操作让 Agent 读取并操作用户明确交给它的某一个原生应用。该能力默认关闭，与内置 `Browser` 工具相互独立，且永不同时操作整个桌面：每次调用都只在一个由用户挑选的作用域内执行。

它可以通过语音触达。实时语音仍然只是语音接口，不获得任何新权限——一句口述请求会变成绑定会话上的工作请求（见[实时语音工作会话集成](/zh-CN/spec/03-runtime/live-work-session)），由现有 Agent 轮次调用工具，会话的模型、权限模式和审批卡片完全不变。语音驱动的电脑操作是任务委派，不是逐帧遥控：一句口述由一个带可见进度的 Agent 轮次来回答，而不是一条持续的控制回路。

| 界面 | 所有者 | 可达范围 |
|---|---|---|
| `Browser` 工具（`pi.browser`，ADR 0170） | 走白名单 CDP 的内置插件 | 仅限内嵌 `WebContentsView` 宿体 |
| `Computer` 工具（本页） | host-core 内置工具 | 一个被授权的原生窗口或应用 |
| 实时语音 | Electron Main 与 Renderer | 音频、转录与工作委派；不做输入合成 |

## 所有权与进程模型

```text
Renderer（挑选器 UI、指示器）
  → Preload IPC → Electron Main（薄层：挑选器、指示器、tools.execute 转发）
    → Rust host-core `computer.*`（窗口、无障碍、合成、截取、
      授权中介、审计）
```

host-core 拥有窗口枚举、无障碍检查、事件合成、屏幕截取、授权中介、动作预算与审计记录。Renderer 永不拿到原生窗口句柄、原生元素引用或输入原语；它只拿到挑选器的展示列表和指示器的授权视图。Agent sidecar 只能通过现有 `host.proxy` 白名单中的 `tools.execute` 触达该能力——不新增代理方法；`computer.*` 不是插件宿主 API，也不出现在插件权限矩阵中。

## 授权与作用域

**作用域授权（scope grant）** 是权限单位。只有用户能签发，且只能通过宿主驱动的挑选器签发。

| 字段 | 含义 |
|---|---|
| `grantId` | 本次授权的身份；出现在每个工具结果和审计行中 |
| `target` | 恰好一个窗口，或一个应用的窗口集合，由挑选器选定 |
| `revision` | 目标的测量几何或身份变化时递增 |
| `inputPolicy` | `confirm-each` 或 `autonomous-in-scope` |
| `capture` | `a11y-only` 或 `a11y-and-pixels` |
| `actionBudget` | 授权关闭前剩余的输入动作数 |
| `idleExpiry` | 墙钟上限；长时间无动作的授权自行关闭 |

规则：

- 模型不能命名、枚举、按标题请求或扩大目标。没有"列出窗口"，也没有"切换目标"动作。解析到授权作用域之外的调用是错误，不是扩权提示。
- 每个桌面实例最多只有一个活动授权，与实时语音的单通话槽位一致。授权属于签发它的会话与轮次链；子 Agent 继承活动授权，但不能创建第二个。
- 创建授权始终是桌面 UI 的显式决定，且没有自动截止期限（ADR 0310）。权限模式 `auto` 不签发授权，口述请求也不能：通话可以请求授权，于是卡片出现在主窗口，而悬浮通话条只提示应用需要关注。
- 用户随时可以撤销：指示器的"停止"、全局快捷键、关闭目标，或关闭该功能。撤销立即生效，并终止进行中动作的剩余步骤。
- 授权从不持久化。重启、Renderer 重载或窗口导航都不会留下授权。

## 绝对拒绝

以下两条拒绝不可通过任何权限模式、设置、授权选项或 `auto` 策略触达：

1. **该能力永不以 PI-Desktop 自身窗口为目标**——审批卡片、设置、密钥界面、实时语音悬浮件、插件视图。向本应用合成输入等于直接绕过权限中介。
2. **当操作系统报告安全输入状态，或焦点落在密码字段时，截取与合成一律拒绝。** 拒绝以错误码上报；该字段内容永不进入快照、截图或日志。

在这两条之上还有一份用户可编辑的应用拒绝名单。其中内置的凭据界面条目——平台钥匙串与凭据 UI、操作系统认证对话框——不可移除。

## 工具契约

`Computer` 是内置高风险工具而非插件工具，因此它的影响面无法被表达成插件作者可以申请的权限。Plan 与 Goal 在权限评估之前就硬拒绝它，与 `Write`、`Edit` 相同：它改变的是工作区之外、宿主无法快照、比对或回滚的状态。

| 动作 | 风险 | 行为 |
|---|---|---|
| `describe_scope` | low | 返回授权视图：目标名称、revision、策略、截取模式、剩余预算 |
| `inspect` | low | 作用域的结构化无障碍树：role、name、是否有值、是否可用、是否聚焦、bounds、按授权生成的不透明 `uid` |
| `screenshot` | low | 裁剪到作用域并缩小的图像，附带 `basis` 令牌；`a11y-only` 授权下被拒绝 |
| `act` | high | 一批有界输入，按 `uid` 寻址，或按坐标配合 `basis` 寻址 |
| `wait` | low | 带显式超时地等待作用域条件（元素出现、变为可用、文本改变） |

`act` 支持 `click`、`double_click`、`right_click`、`set_value`、`press_keys`、`scroll` 与 `select`。每一项都优先通过平台无障碍动作派发，只有在不存在对应动作时才回退到合成。

元素身份以无障碍为先。`uid` 不透明、按授权生成，并在 revision 变化时失效。`inspect` 不返回元素取值，只返回是否有值，因此读取字段内容是一个用户能在转录中看到的显式 `inspect` 结果字段，而不是枚举的副作用。

### 坐标与新鲜度

坐标输入只以 `act` 配合 `basis` 的形式存在：`basis` 由同一作用域的 `screenshot` 签发，携带授权 revision 与测得的窗口几何。宿主在合成前立即重新校验 `basis`，并拒绝过期值。因此：

- 模型永远无法派发盲点击。没有截取就没有 `basis`，没有 `basis` 就没有坐标。
- 目标在截取与动作之间移动、改变尺寸、revision 变化或失去焦点时失败关闭，而不是点击此刻占据那片像素的东西。
- 坐标相对作用域，并被夹到测得的窗口边界内。越界坐标是错误，不是被夹紧后照样点击。

## 权限流程

权限模式治理的是授权，不是每一次按键。

| 阶段 | `ask` | `accept-edits` | `auto` |
|---|---|---|---|
| 创建授权 | 确认（桌面 UI） | 确认（桌面 UI） | 确认（桌面 UI） |
| 活动授权内的 `inspect`、`screenshot`、`describe_scope` | 允许 | 允许 | 允许 |
| `confirm-each` 下的 `act` | 每批确认 | 每批确认 | 每批确认 |
| `autonomous-in-scope` 下的 `act` | 不可用 | 允许 | 允许 |
| Plan / Goal | 硬拒绝 | 硬拒绝 | 硬拒绝 |

`confirm-each` 是默认值，也是 `ask` 下唯一可用的输入策略。`autonomous-in-scope` 需要在授权时显式选择。两种策略都受动作预算、空闲过期、每动作作用域重校验以及终止开关约束。`Computer` 不存在 `allow-session` 授权：作用域授权本身就是会话级决定，而按工具名授权会活得比它被批准针对的那个目标更久。

## 平台支持

| 平台 | 检查与输入 | 截取 | 说明 |
|---|---|---|---|
| macOS | `AXUIElement`，需 Accessibility TCC 授权 | ScreenCaptureKit，需屏幕录制 TCC 授权 | 安全输入状态会同时拒绝两者 |
| Windows | UI Automation 加 `SendInput` | 桌面复制 / 窗口截取 | 由更高完整性级别进程拥有的窗口被拒绝，绝不静默丢弃 |
| Linux / X11 | AT-SPI 加 XTEST，尽力而为 | X11 截取 | 需要无障碍总线；工具包不支持时如实上报，不做猜测 |
| Linux / Wayland | 拒绝输入 | 门户屏幕投送 | 不存在可移植的合成输入；截取仍可用 |

任何尚未实现的平台或阶段都返回明确的不支持错误码。缺失的能力永不表现为挂起，也永不以成功回报空操作。

## 设置与 UX 界面

- 电脑操作默认关闭。打开开关不会创建授权、申请操作系统权限、截取画面或枚举窗口。
- 体检视图按平台报告操作系统权限状态（屏幕录制、无障碍、无障碍总线、会话类型），并区分"未申请"、"已拒绝"与"本平台不支持"。被拒绝的 TCC 授权不得呈现为功能损坏。
- 目标挑选器由宿主驱动，仅在打开期间展示列表。它是选择目标的唯一方式。
- 授权指示器在授权存续期间始终可见，标明目标、剩余预算与截取模式，并带有"停止"。应用退到后台时它仍然可见，实时语音通话条也会反映活动授权。
- 授权卡片在批准之前说明正在批准哪种截取模式，并说明 `a11y-and-pixels` 意味着目标的截图可能进入会话转录。

挑选器、指示器、授权卡片与体检视图的组件级措辞随实现变更落地，不在本页。

## 审计与隐私

每一次授权与每一个动作都通过现有 `audit.*` 落盘：授权身份、目标身份、动作类型、元素 role 与 `uid`、以及结果。键入的文本只记录长度，绝不记录取值。像素永不写入审计日志。

进入模型的截图走现有的无损工具图片存储路径，裁剪到授权作用域并缩小；因此在 `a11y-and-pixels` 下它们会留存在会话转录里——这正是 `a11y-only` 存在的原因，也是授权卡片要点明该选择的原因。被截取的像素、无障碍取值与从窗口读到的文本都是不可信输入：它们是数据，绝不是能改变 Agent 作用域、工具、授权或权限的指令。

## 错误码

错误码登记在 [08-error-codes](/zh-CN/spec/03-runtime/08-error-codes) §3.10，统一使用 `COMPUTER_` 前缀。契约是每一种拒绝都可单独归因：功能关闭、无授权、作用域越界、`basis` 过期、revision 过期、预算耗尽、授权过期、拒绝自我目标、拒绝安全输入、目标在拒绝名单上、缺少操作系统权限、目标提权、平台不支持、元素未找到或不可操作，以及超时。

## 验证与限制

- 在任何部分交付之前，自动化覆盖必须包含：自我目标拒绝、安全输入拒绝、`basis` 与 revision 过期拒绝、坐标夹取、预算与过期关闭、单授权互斥、Plan/Goal 拒绝，以及不支持平台的路径。
- 无障碍树、合成路径与截取路径都与平台相关，无法用 fixture 证明。各平台的真机验收是单独且需显式授权的矩阵；fixture 全绿不等于真机通过。
- E2E 场景列在 [04-e2e-test-plan](/zh-CN/spec/06-delivery/04-e2e-test-plan) 的 `E2E-COMPUTER-USE-` 前缀下。
