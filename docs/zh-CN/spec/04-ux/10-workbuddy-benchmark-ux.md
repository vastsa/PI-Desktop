## 1. WorkBuddy 是什么（观察）

consumer/prosumer“人工智能工作伴侣”：聊天优先的桌面应用程序，其单元
工作是一项**任务**（有目标的对话），在**空间/下组织
项目**，由**专家（角色）·技能·市场扩展
连接器**，加上**自动化**（计划任务）。它是人物和
模板重； PI-Desktop 需要大量开发人员和工作空间。这里的值
是交互模式，而不是产品范围。

## 2. 观察 IA

```text
+----------------------------+------------------------------------------+
| 侧边栏 | 主窗格 |
| 收起·搜索·筛选（上） | 每个目标标头 (tabs/actions) |
|  新建任务                   | 内容 |
| 助理（当地助理） |                                          |
| 项目（项目） | 聊天目的地： |
| 专家·技能·连接器（弹出） | 文字记录 + 浮动输入框 |
| 自动化（自动化） | 输入框：+·权限选择·模型选择· |
| 更多（弹出窗口：文件/知识库/ |            语音 · 发送                    |
|        灵感)                | AI 内容免责声明页脚 |
| 任务 (N) — 最近的任务 |                                          |
| 空间 (N) — 空间 |                                          |
| 页脚：头像·通知·分享 |                                          |
+----------------------------+------------------------------------------+
```

值得注意的每屏细节：

- **聊天/任务**：标题中带有搜索/共享/历史/面板的标题
  图标；每条消息的操作行（复制、like/dislike、TTS、重试、分享等）
  加上**代币成本芯片** (`共消耗 ◇2.85`) 和内联模型徽章；全球
  免责声明“内容由AI生成，请授权重要信息”。
- **输入框**：单药丸；占位符教授语法（“@引用对话文件，
  /调用技能与指令");左集群 `+` 和 **权限模式下拉列表**
  (“默认权限”);右集群模型选择器（“自动”/命名模型）、麦克风、发送。
- **助理（助理）**：持续的“本地助理”与
  **标题中的连接状态**（“已连接：微信小程序”+齿轮）—
  Assistant 被呈现为一个具有集成的实体，而不仅仅是一个线程。
- **项目（Projects）**：带有英雄的登陆页面（标题，单行值道具，
  插图），主要CTA“新建项目”，“我的项目”卡列表与烤肉串
  菜单，然后是 **“从模版创建”模板库**（PRD 流程、市场研究、
  团队知识库、交付、错误跟踪）。
- **自动化（Automations）**：选项卡定时任务/运行记录；空状态（图标+
  一行字 + 主要 CTA）；下面是约 12 个食谱的 **模板库**
  （每日人工智能新闻、每周报告、会议准备……）所以空状态仍然存在
  提供一键式价值。
- **专家·技能·连接器**：侧边栏项目打开3向弹出窗口；该页面有
  分段选项卡（专家/技能/连接器）、搜索、“我的专家”、特色场景
  横幅卡、类别筹码行、排序（综合/最热/最新）、丰富的人物角色
  卡片（头像、口号、能力标签）。
- **更多**：次要目的地的溢出弹出窗口（我的文件，腾讯文档，
  ima 知识库、乐享知识库、灵感) — 将轨道保持在约 6 个主要项目。
- **我的文件（My Files）**：不是文件管理器——一个**神器浏览器
  任务输出**。选项卡任务成果 / 云端网盘（云盘同步）；类型过滤器，
  跨“文件、任务或工作空间”搜索，收藏夹切换；一张桌子
  （名称/类型/更新者/更新者/大小）其行**分组为
  生成它们的任务**（组标题显示任务名称+计数，例如
  “未分组·1个任务”→任务→main.js/styles.css/index.html)。每个
  稍后可以找到代理生成的可交付成果，而无需重新打开
  谈话。
- **空间（Spaces）**：任务和页脚之间的侧边栏部分。一个空间
  **绑定到本地目录**（将鼠标悬停在空间“工具”上会显示
工具提示，例如 `/Users/example/Projects/tools`) 和 ** 内联展开以列表
  任务在其中运行**；悬停时的行操作：`+`（此中的新任务
  空间）和 `…`（管理）。两个列表中的任务都带有状态徽章 - 绿色
  点 = 正在运行，红色 `!` = 失败。 Cloud/collab 项目 (项目) 也出现
  在本节中，“空间”是“工作发生的地方”的总称，
  本地文件夹或共享项目等。
- **新手引导**：第一个助理消息是结构化面试
  （name/style 代表代理人；如何称呼您、城市、当前焦点） —
  通过对话而不是表单向导进行个性化。

## 3. 采用（PI-Desktop 的规范更改）

下面的每一项都是一个具体的建议；决策将记录在决策日志中。

### 3. 1 Composer中的权限模式
WorkBuddy 将权限姿势放在发送按钮旁边。 PI-Desktop
公开与 Composer 芯片相同的控件（当前有效模式：
`Ask every time / Accept edits / Auto`）打开一个小菜单。菜单显示
仅这三种模式，直接标记有效选择；它没有
表面全局默认或继承来源。选择一种模式会创建一个
每个会话覆盖。这补充而不是取代内联
[03-permission-ux](/zh-CN/spec/04-ux/03-permission-ux) (D132) 中的权限卡。

### 3. 2 每条消息元：成本+模型
在助理消息上采用内联 **token/cost 芯片和模型徽章**
（默认情况下折叠到消息操作行中；悬停以展开
input/output/cached 细分）。运行时使用中数据已存在
事件。

**在 D103 中采用（仅限代币第一刀）**：完成的辅助回合显示
模型徽章和答案下的紧凑 Codex 风格上下文检查器。检查器显示小环中
的剩余上下文百分比；点击触发器后打开轻量摘要面板，展示剩余/窗口
计数以及无卡片的本轮/速度数值。提供商的 input/output/cache/reasoning
用量压缩为一条精确摘要；工具用量压缩为一条聚合摘要，展示工具种类、
调用次数和估算令牌数。默认视图省略逐工具行、占比条、徽章和解释性
估算文案。生成率是完整回合快照而不是实时流媒体计数器。上下文窗口总计
来自代理 sidecar 使用的相同 `pi-ai` 模型元数据，未知模型才回退到提供商
元数据和默认窗口。工具估算仍与精确提供商总量分开，因为提供商不会公开
每个工具的上下文分配。
货币定价仍然推迟。重新生成可以作为一个安静的操作
复制旁边的芯片并重写当前回合（D105）；当多个
存在变体，root 用户上会出现 ChatGPT 样式的 `current / total` 寻呼机
恢复存档的分支（D109）。完成的辅助行也暴露了 Fork
以及可逆编辑，同时省略删除；两次编辑都分散成孤立的
会话，以便源 cache/runtime 保持不变 (D134)。

### 3. 3 空状态下的模板库
WorkBuddy 永远不会交付完全空的状态：自动化和项目都是配对的
带有点击实例化模板的空英雄。 **规格**：预定页面
空状态获得 4-6 种开发方法（每晚测试运行、依赖更新
摘要、PR 审查扫描、变更日志草案）；设置项目存档保留
它的表，但在空时会获得“从模板开始”行。

### 3. 4 教学输入框中的占位符
将静态占位符替换为语法教学占位符：
“描述任务 — @ 表示参考文件，/ 表示命令”。空荡荡的家继续
这个直接进入的界面专注于英雄、可选的入门和底部
输入框，无需添加开发人员入门卡或上下文快速操作
层（D204/D206）。

### 3. 5 次要目的地的溢出“更多”弹出按钮
保持侧边栏的主要物品数≤6。随着目的地的增长（原木、
文件、知识、未来面板），将它们放置在“更多”弹出按钮下，而不是
加长铁轨。

### 3. 6 对话式入门（首次运行）
通过第一助理补充新手引导清单（05-新手引导）
轮流采访用户（项目、首选语气、护栏）以及
将结果写入工作区 memory/config — 一种伪装成聊天的表单。

### 3. 7 工件视图（来自我的文件）
会话生成的文件用户稍后无法在不滚动的情况下找到
成绩单。 **采用 D128 中的第一步**：单击文件工件会创建一个
路径键控、可关闭的工作面板选项卡和成功的工作区 Write/Edit
工件打开审查。 **在 D179 中采用**：转录本还放置了一个
每次成功的文件修改后立即显示消息范围的审查卡；它的
状态、+/- 总计和可扩展块保持附加到该工具行，而不是
而不是成为全局页脚条目。这些渲染器选项卡和卡片是
短暂的观点，不是第二次
持久化模型；主机拥有的 `artifacts` 表仍然具有权威性。
未来的专用工件目的地可能会列出按会话分组的文件
包含名称/种类/会话/时间列和 Finder/diff 操作。跳过
云驱动选项卡（范围内没有云存储）。

### 3. 8 工作空间范围的会话树（来自空间）
WorkBuddy 将任务嵌套在它们运行的文件夹绑定空间下，使用 `+`
（此处的新任务）悬停和状态徽章（运行点/失败标记）
任务。 **在 D093 中采用和扩展**：PI-Desktop 渲染每个保留的、
路径键控项目作为一个紧凑的、可独立折叠的组，然后是
用于无路径会话的临时会话组。每个目录标题是
单一披露目标（V 形、文件夹、标签和剩余行命中
区域），而 `+` 和溢出操作出现在 hover/focus 上。活跃项目
仍然是唯一选定的主机工作区；保留组不会创建
并行工作区单例。这取代了 D088 的单电流项目
侧边栏限制，同时保留其精确路径和临时边界。
**在D135中细化**：每个对话行使用固定的引导状态槽
具有独特的颜色和几何形状：强调蓝色选择环，警告橙色
呼吸进行中点，成功 - 绿色检查，错误 - 红色警报。进行中
优先于选择，选择优先于最新的最终结果，并减少
运动使正在进行的点保持静止。

## 3. 9 转录本密度和用户板比对
WorkBuddy 的任务记录使用户轮流保持为紧凑的右侧板，并且
助理变成全角透明散文，在下面有安静的悬停动作
每个回合。 **D101 中采用**：PI-Desktop 保持开发人员工具的限制
（没有吉祥物，没有 like/dislike）但会增加行间距，使用户右对齐
`min(78%, 560px)` 处的板，软化 border/shadow 处的板，并显示副本
仅限 hover/focus-within 上的芯片。流媒体助手答案使用薄
重音左规则而不是重脉冲帧。

## 4. 谨慎适应

- **Assistant-with-integrations 标头**（“已连接：X”）：良好的模式
  显示每次会话的 MCP/connector 运行状况；适合作为小型连接器
  上下文面板中的状态簇，而不是聊天标题。
- **角色市场**：超出了商店的范围，但**卡片语法**
  （avatar/icon、一行标语、功能标签、类别芯片、排序）是
  随着目录的增长，插件页面的正确模板。
- **语音输入/TTS**：备注为未来；不是 MVP。

## 5. 拒绝

- **吉祥物艺术品**漂浮在文字记录上 - 与
  受限的开发工具美学（07-ui-design-system）。
- **Like/dislike + 在每条消息上分享** — 无需后端服务；保留
  复制/重试/（成本筹码）的操作行。
- **消费者模板内容**（睡前故事、壁纸）- 替换为
  §3.3 中的开发者配方。
- **一揽子人工智能免责声明页脚** - 在每个输出的工具中都是多余的
  是可检查的；许可用户体验已经承载了信任面。

## 6. 开放式问题

1.输入框权限芯片是否写入设置或保留
   会话范围？ （建议：会话范围，设置不变。）
2. 芯片货币成本：仅代币，还是按提供商定价？
3. 预定模板：硬编码还是插件贡献？
