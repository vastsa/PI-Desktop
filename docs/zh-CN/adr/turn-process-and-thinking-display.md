# ADR turn-process-and-thinking-display：回合过程与思考展示

## 背景

模型在回答一次用户请求之前，可能多次交替输出推理、工具调用和进度文字。仅使用分散
的活动组，会让进度文字与最终回答处于同一视觉层级；仅使用一个扁平的过程容器，又会
让较长的工具或搜索序列难以浏览。部分用户还需要稳定的思考状态提示，而不是快速变化
的推理正文。

## 决策

所有已加载的助手回合条目都使用同一套回合过程展示：投影为按时间顺序排列、可折叠的
过程片段，以及其后的最终回答。思考、工具和中间进度文字跨这些片段按原顺序保留。流式
输出时，暂定为回答的末尾助手文字保持可见；如果随后出现工具或思考活动，该文字会移入
过程，但不会改写已存消息。`UiMessage` 没有语义化的最终回答标记，因此渲染器不根据
措辞猜测。用户消息、系统消息和压缩分隔线继续保留原有回合边界。

过程是分段的，而不是一个扁平容器。非 Bash 活动形成普通活动组：两个进度段落或 Bash 行
之间的一段连续工具、搜索或思考活动，并且仅在当前思考偏好下至少有两个可见项时出现。
单项活动直接使用自身披露；被隐藏的思考不会制造多余的组包装。现有 Task 拓扑仍是其片段
的容器，不会在普通活动组中重复渲染。

Bash 和 run 别名被排除在所有过程披露之外——既不属于回合级过程披露，也不属于普通活动组
——而是作为独立行渲染，即使所有组都收起也保持可见。相邻的 Bash 行各自保持独立，且
Bash 行的详情在用户手动打开之前保持收起。进度段落之间的其他操作仍会形成可按时间顺序
折叠的活动组。

活动组的折叠默认值是统一的，不依赖思考偏好。拥有当前执行片段的普通活动组默认展开，
仅在用户未操作时于完成后收起；其他已完成组默认收起。只要活动组中记录过失败或被拒工具，
尚未被用户接管的活动组就会在后续恢复期间保持展开，并在回合完成后收起。无论任何组是否
收起，Bash 行都保持可见。

思考偏好是一个布尔值 `showThinking`。当它为 false 时，活动思考指示器保持可见，而已完成
的思考行和摘要会被隐藏，空的纯思考容器会被省略；已存推理仍会保留，因此重新打开该偏好
会恢复已完成的思考行和摘要。被隐藏的思考不会制造空的组包装。

本决策早先引入的叶子默认值后来被移除。条目载荷都不会自动展开：工具调用、托管搜索或
计划行在用户打开之前始终只是标题行，无论它位于活动组的哪一项，且与思考偏好无关。
组默认值不变，打开一个已收起的祖先仍会恢复已保留的条目选择，不会展开所有后代。

每个标题只切换自己的层级。父子状态彼此独立：收起父级会保留后代选择，重新展开会恢复
这些选择，同级组不是互斥手风琴。用户操作某个条目时，会把所属组标记为用户接管，但不会
切换该组；完成事件不得收起包含用户已展开、聚焦或选择内容的容器。只要所属的保留会话
窗格仍存在，手动选择就跨流式更新、完成、偏好切换、单项变组和行重新挂载保留。窗格淘汰、
会话删除或渲染器重启会释放这些展示状态；它们不写入消息或宿主设置。

搜索和导航只展开目标所需的祖先路径：拥有该消息的过程片段和活动组。条目级精确定位不在
本次范围内，各行详情仍由各自的折叠控制。同一请求重新渲染时，不会反复覆盖用户之后的
手动收起。被偏好隐藏的推理会保持隐藏，直到用户打开 `showThinking`。助手错误、中止后的
末尾部分回答、权限／提问／计划／目标决策及其他待处理操作面必须位于隐藏过程之外，
无需展开过程即可操作。

“设置 -> AI -> 默认项”提供一个 `Show thinking` 布尔开关，以可选的 `showThinking`
`AppSettings` 字段持久化。缺失或非布尔值会回退到旧版 `thinkingDisplayMode` 字段：
显式 `compact` 隐藏推理，而 `detailed`、未知值或缺失值都显示推理。旧字段为持久化设置的
兼容性而保留，不再在界面中暴露。该偏好只改变展示，不改变提供商思考级别、运行时或模型
上下文、已存推理、导出、权限、执行或复制载荷，也不控制过程片段或活动组的折叠。过程标题
使用已记录的计时、直接工具／搜索计数、运行状态和问题计数；不会重复计算委派子任务，
也不会把单个失败工具误报为整个助手回合失败。

## 结果

- 按时间顺序排列的可折叠过程片段让最终回答和待处理操作保持可达，并且即使所有组都收起，
  Bash／run 行也保持可见。
- 活动组的折叠默认值统一：运行中的工作保持可见，未操作的已完成组默认收起，
  无论思考偏好如何都保留用户明确的披露选择。
- 当 `showThinking` 为 false 时，活动指示器保持可见，而已完成的推理行和摘要被隐藏。
  已存推理仍会保留，重新打开偏好时重新出现。
- Bash 和 run 别名作为独立行位于所有过程披露之外，因此命令密集的回合无需把相邻命令
  折叠在一起即可浏览。
- 披露记忆是以稳定回合、组和条目标识为键的窗格展示状态，不是持久化转录契约，也不
  属于中央工作流 store。
- 只对已加载的转录条目分组；不会重建未加载历史，也不会跨压缩边界合并回合。
